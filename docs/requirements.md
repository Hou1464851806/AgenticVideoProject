# Agent 驱动的视频编排剪辑系统：首版完整需求

状态：产品与架构基线已确认。本文汇总整体核对 Q58 已确认的讨论，并于 2026-10-12 补充已确认的统一自然语言流程，作为首版 MVP 的总需求与验收依据。已有实现和真实验证见 implementation-status.md；新增流程待实施，本文不代表所有功能或验收已经通过。

## Problem Statement

个人用户拥有长视频或多个视频素材，却需要耗费大量时间查找内容、判断片段边界、安排顺序并导出视频。传统剪辑界面要求用户直接操作时间线；单轮模型回答又往往无法保留修改关系、提供可核查的素材出处或生成可执行的剪辑结果。

用户需要在自己的项目中上传素材，以自然语言反复表达需求，让系统理解和查找视频内容、提出有依据的编排剪辑方案，并在用户确认具体方案版本且明确要求导出后生成成片。整个过程应允许检查片段、修改方案、查看历史与恢复中断，同时控制本机资源和模型调用开销。

## Solution

提供面向个人用户的项目工作区，以素材库、对话、播放器及结构化结果承载完整制作流程。不同账号的项目互相隔离，每个项目可有多个制作会话与多份编排剪辑方案。

首版交付三条用户主线：

1. **长视频拆短视频**：优先支持中文访谈、课程、讲解等讲话视频。Agent 按主题、数量、时长及内容要求选出观点完整的片段，形成多个成片定义，用户检查、修改后分别导出。
2. **多素材基础混剪**：从多个视频选段，按用户要求组织为一条视频，支持硬切、原声和自动字幕，与第一条主线共享理解、检索、版本及渲染能力。
3. **视频内容查询**：通过对话检索语音、画面和可见文字，返回素材出处、观察时间或范围及证据，支持跳转播放；不要求为了查询先创建剪辑方案。

以统一自然语言对话为主要操作方式，需求类型、证据来源及检索方式由系统选择，制作和澄清表单作为可选补充。方案修改生成不可变新版本，允许从任何历史版本继续修改。低清效果预览由用户明确请求，对话或按钮均可；正式渲染必须同时具有具体版本的确认和另行明确导出指令。

2026-10-12 确认近期先完成一条讲话短视频或一条跨素材混剪的完整对话流程，包括指定片段修改；随后扩展多条生成和批量导出。这是交付顺序，不削减原 MVP 的最终范围。完整九项决定及代码职责见 [统一自然语言设计](natural-language-workflow-design.md)。

### 领域含义

术语沿用项目领域词汇：素材是原始媒体；编排剪辑方案描述如何制作；方案版本是一次成功修改后的完整历史状态；成片定义是一条待生成视频的内容与规格；成片是实际渲染产物。候选片段尚未选入方案，剪辑片段已经被选入。上传会话与制作会话分开，对话轮次与方案版本分开。

原始观察证据记录语音、画面或可见文字及其来源和时间；检索单元组织可搜索内容并引用证据；素材摘要只用于概览与导航。分析覆盖说明已经处理的范围和类型，不能把摘要或模型自述直接当作精确剪辑依据。

## User Stories

以下故事按中文表达“作为某类用户，我希望完成某项操作，以便获得相应收益”。全部属于首版范围，实施顺序不削减最终交付范围。

### 账号与项目

1. 作为个人用户，我希望使用用户名和密码注册、登录及退出，以便独立使用系统。
2. 作为个人用户，我希望创建自己的项目并查看项目列表，以便组织不同视频制作目标。
3. 作为个人用户，我希望只访问自己的项目、素材、对话、证据和产物，以便保持内容私有。
4. 作为个人用户，我希望在同一项目内建立多个制作会话，以便独立探索不同需求。
5. 作为个人用户，我希望在同一项目内保存多份编排剪辑方案，以便分别管理不同制作方向。

### 上传与素材库

6. 作为个人用户，我希望向指定项目上传一个或多个视频，以便建立素材库。
7. 作为个人用户，我希望上传大文件时使用分片并看到进度，以便了解传输状态。
8. 作为个人用户，我希望断网后只重试失败分片，以便避免重新传完整文件。
9. 作为个人用户，我希望暂停并继续上传，以便主动安排网络和本机资源。
10. 作为个人用户，我希望刷新后重选原文件恢复已有上传，以便继续利用已完成分片。
11. 作为个人用户，我希望同名但内容不同的文件不能误接旧上传，以便保证素材完整性。
12. 作为个人用户，我希望临时上传授权到期后重新获取授权，以便继续原上传而不丢失已完成部分。
13. 作为个人用户，我希望取消上传并看到清理状态，以便结束不需要的传输。
14. 作为个人用户，我希望收到文件大小、数量、时长、项目容量或实际剩余空间不足的明确提示，以便及时调整上传计划。
15. 作为个人用户，我希望区分传输完成、媒体验证通过和内容分析就绪，以便知道目前能做什么。
16. 作为个人用户，我希望损坏、不可解码或超出支持限制的文件被拒绝并给出原因，以便替换素材。
17. 作为个人用户，我希望在素材库查看媒体信息和各分析阶段状态，以便选择可用素材。
18. 作为个人用户，我希望播放已验证素材并定位到某个时间，以便核查内容。
19. 作为个人用户，我希望隐藏不想继续选用的素材，以便整理素材库并保留历史方案的来源。
20. 作为个人用户，我希望恢复隐藏素材，以便再次将它用于新的编排。
21. 作为个人用户，我希望删除没有受保护引用的素材，并在删除被引用素材时看到阻止原因，以便避免破坏历史方案。

### 视频理解与检索

22. 作为个人用户，我希望上传后自动进行基础内容分析，以便减少重复手动准备。
23. 作为个人用户，我希望语音分析先完成时就能查询讲话内容，以便不必等待全部视觉分析。
24. 作为个人用户，我希望分别了解语音、视觉和检索索引是否就绪，以便理解能力可用范围。
25. 作为个人用户，我希望通过自然语言查找主题和意思相近的内容，以便不必知道原话。
26. 作为个人用户，我希望查找人名、数字和具体短语，以便精确定位细节。
27. 作为个人用户，我希望查找视频中出现的场景或画面内容，以便选择适合的镜头。
28. 作为个人用户，我希望查找已分析画面中的可见文字，以便定位屏幕信息。
29. 作为个人用户，我希望每个命中给出素材、时间及证据，并能跳转播放，以便核验回答。
30. 作为个人用户，我希望系统区分“语音提到”和“画面出现”，以便避免误用素材。
31. 作为个人用户，我希望查看候选附近的上下文，以便判断内容是否完整。
32. 作为个人用户，我希望系统在预算内复查候选区间，以便改善稀疏画面采样的判断。
33. 作为个人用户，我希望额外深入分析超出预算时先收到说明和选择，以便决定是否承担更多调用。
34. 作为个人用户，我希望未命中时了解已分析范围和可能遗漏，以便知道是否需要继续查找。
35. 作为个人用户，我希望失败阶段可恢复而不重复已成功的分析，以便节约时间和模型费用。

### 多轮对话与工作区

36. 作为个人用户，我希望通过多轮自然语言描述主题、素材范围、数量、时长与禁用内容，以便逐步形成制作需求。
37. 作为个人用户，我希望看到可纠正的制作需求简报，以便核对系统理解并通过新消息修正。
38. 作为个人用户，我希望关键条件不明或相互冲突时收到澄清问题，以便避免生成方向错误的方案。
39. 作为个人用户，我希望低影响选项采用说明过的默认值，以便尽快得到可检查初稿。
40. 作为个人用户，我希望回答明确的问题并继续原轮次，以便保持需求和回答关系。
41. 作为个人用户，我希望等待澄清时可以取消或明确开始新需求，以便改变制作方向。
42. 作为个人用户，我希望发送时明确引用素材、方案版本、成片定义或片段，以便“第二段”等指代有确定对象。
43. 作为个人用户，我希望看到阶段进度、简短活动说明和最终结果，以便了解任务正在做什么。
44. 作为个人用户，我希望在同会话忙碌时继续编辑输入草稿，并收到不能并发发送的提示，以便避免隐式排队和上下文竞争。
45. 作为个人用户，我希望不同制作会话拥有独立上下文，以便分别开展查询或制作。
46. 作为个人用户，我希望关闭或刷新页面后任务继续，并能恢复消息与状态，以便不中断耗时处理。
47. 作为个人用户，我希望显式停止当前任务，以便结束不需要的计算。
48. 作为个人用户，我希望失败后关联原需求重试，以便不重复消息或已提交的方案版本。
49. 作为个人用户，我希望查看完整公开聊天历史，长对话仍保留明确条件，以便继续之前的制作。
50. 作为个人用户，我希望在素材、对话、播放器和结构化结果之间方便操作，窄屏仍能使用，以便完成检查与制作。

### 方案生成与修改

51. 作为个人用户，我希望从一段讲话长视频生成多条符合主题的短视频方案，以便快速提取有价值内容。

55. 作为个人用户，我希望通过“替换第二段”“更紧凑但保留结论”等对话局部修改，以便少操作剪辑界面。

58. 作为个人用户，我希望手动调整片段顺序，以便快速验证另一种编排。
59. 作为个人用户，我希望每次成功修改都保存完整新版本，以便保留历史与修改关系。

## Implementation Decisions

技术部分记录已经确定的职责、约束与交互语义。具体类名、目录、表名、路由和依赖版本不是本需求的稳定约束。

### 产品模型、版本与授权

1. **个人与私有项目**：多个独立用户名密码账号，无团队共享。权限由业务后端验证，项目标识、模型参数或前端传参不能成为授权依据；素材链接、检索、消息、任务和产物均遵守同一项目边界。
2. **统一多输出模型**：项目包含素材、制作会话和多份方案；每个方案版本保存全部成片定义，每个成片定义包含有序素材片段及输出要求。拆短视频是多个输出，混剪是一个输出内跨素材选段。修改一个输出也生成整个方案的新版本。
3. **不可变历史**：Agent 与手动修改都经校验后追加版本，不能原地覆盖。版本序号是创建顺序，修改来源是实际基准。V1、V2、V3 存在后基于 V1 修改，应追加 V4 且来源为 V1；查看切换不生成版本。
4. **明确执行对象**：消息接纳时保存素材范围、显式引用和发送时查看上下文；理解后由业务后端校验并固定实际方案基准、目标输出或片段，首次建方案由后端分配目标。明确引用优先，其次发送时查看版本，尚未打开方案时使用本会话最近生成的方案；存在多个可能对象或冲突时澄清。视图切换不改变运行输入，完成后不强制切换用户正在查看的版本。
5. **两种串行约束**：每个制作会话只有一个活动逻辑轮次，忙碌时不自动排队新需求；同方案同时只有一个编辑者，Agent 编辑期间禁止手动及第二次修改。不同会话独立运行仍须遵守同方案互斥。纯查询不取得方案编辑权。
6. **确认与正式导出**：确认只绑定具体不可变版本。旧版确认保留，新版不继承；每次正式导出都要明确用户指令，并重新校验版本确认、权限与素材引用。自然语言指令可由受控业务路由处理，Agent 推测或自行规划不能制造确认与导出授权。
7. **预览与导出分开**：低清合成预览无需正式确认，但必须由用户主动请求。片段预览直接播放源素材区间。正式输出可选部分或全部成片定义，每条独立记录结果，整体展示部分完成。

### 服务与基础设施

8. **服务职责**：Vue 3 + TypeScript 提供工作区；Spring Boot 业务后端管理权限、业务持久状态、版本、确认及任务；独立 Spring Boot 媒体 Worker 执行 ffprobe、FFmpeg、媒体验证与音频/画面提取；Python FastAPI + LangGraph 管理固定分析、模型适配、检索和对话 Agent。业务后端与媒体 Worker 独立进程及资源限制，允许共享必要 Java 协议。
9. **权威数据**：PostgreSQL 保存业务元数据、上传恢复记录、证据、消息、版本、确认、任务、公开事件、用量及 Outbox。LangGraph checkpoint 使用独立数据范围和权限，不能代替业务历史。Qdrant 是可重建索引，Redis 是可失效缓存及短期辅助。
10. **文件与通知**：PGSTY Silo 保存原始和派生媒体，使用兼容 S3 协议；RabbitMQ 派发耗时任务。普通查询和受控工具通过 HTTP，浏览器经业务后端统一鉴权并订阅 SSE。消息队列不搬运视频二进制或长期密钥。
11. **本机起步、可扩展**：通过 Docker Compose 在现有 MacBook 部署，以 Linux arm64 容器和 CPU 媒体处理为验证基线；不依赖未验证的宿主 GPU 能力。通过持久卷、配置化资源限制、独立执行服务保留迁移和扩容能力，首版不建设分布式集群。

### 上传、容量与素材发布

12. **可恢复直传**：浏览器使用短期授权向 Silo 做 S3 multipart 直传，后端持久管理上传会话、对象身份、分片清单、写入资格、空间/数量预留及完成/取消。分片只作传输拆分，不改变视频内容，不增加独立续传服务。
13. **恢复与完整性**：分片重试有上限，成功片保留；刷新后重选同一文件，通过有界增量哈希核对内容身份。客户端文件名、大小或哈希不能替代服务端验证；媒体 Worker 独立核对字节数、全文件哈希和可解码媒体信息后才发布可用素材。多个标签页不能竞争续写同一上传。
14. **跨系统完成与取消**：核对实际分片后完成对象，处理响应丢失、重复完成、完成与取消竞争及在途上传。对象完成、素材验证、分析就绪是不同状态。取消/过期后核对实际残留并反复清理，未真正删除的字节仍计入占用。
15. **初始可配置限制**：单文件不超过 2 GiB，单素材不超过 60 分钟，单项目不超过 10 个视频，项目原始素材不超过 5 GiB；未完成上传最后活动后 24 小时过期；正式渲染并发为 1。GiB 表示 2³⁰ 字节。预留与空间检查覆盖未完成上传、原始文件、派生媒体、执行工作区和输出，不能只检查时长或素材数。

### 理解、时间与检索

16. **模型职责与适配**：Qwen 提供 ASR、VLM 和文本 Embedding，优先使用百炼；DeepSeek 官方 API 提供对话、理解和工具决策。接口优先采用 OpenAI 格式，时间戳或异步能力不足时使用提供方原生接口。内部适配层复用这些能力，首版不独立部署模型网关；提供方、模型、地域、参数和用量记录可追踪。
17. **基础分析与按需补查**：有音轨时分析完整语音；视觉使用稀疏代表帧和必要场景变化邻近帧，不将编码 I 帧等同于语义代表帧。重复画面保留实际出现时间。深入理解按需复查候选区间；无候选时允许预算内扩大采样，但不承诺每帧覆盖。
18. **三层内容与来源**：原始观察证据、检索单元、素材摘要分开保存，记录素材、时间、来源、分析规则及模型版本。语音提及、画面观察、可见文字分别标识；检索单元窗口不直接作为剪辑切点，单帧观察时刻不伪装成整段持续场景。
19. **统一时间映射**：素材片段使用原素材时间轴的毫秒左闭右开区间，满足起点小于终点且不越界；保存音画起点、提取起点与实际帧时间的映射，处理可变帧率等情况。字幕映射到成片时间轴，选段和重排后重新计算；版本保存字幕内容及时间，预览不重新调用 ASR。
20. **分阶段可用**：媒体准备、语音分析、视觉分析及各索引分别记录就绪；语音就绪可先查询和选段。失败只重试受影响阶段；Embedding 或索引故障不重跑成功的 ASR/VLM，已有向量批次与证据可恢复索引。
21. **混合检索**：Qwen 文本稠密向量与 Qdrant 原生中文 BM25 并行召回、RRF 融合，保留 PostgreSQL 参数化原文短语查找作为字面补充。中文索引和查询分词一致，各通道在召回前限定权限、项目和有效代次，项目 IDF 统计范围另行限定。先比较语义单路、BM25 单路及融合效果，预留精排接口而不先强制增加模型。
22. **代次与覆盖**：新索引代次写入、验证后由业务后端发布；查询固定有效代次，旧尝试、未完成或取消结果不能进入在线召回。更换向量模型或维度建立新索引，不混用不兼容向量。结果报告实际分析覆盖，未命中表示在已分析范围内未找到，不宣称内容绝不存在。

### Agent、多轮对话与前端

23. **有限自主单 Agent**：固定素材分析和程序提交流程，主要编辑 Agent 采用外层受控阶段、复杂请求的轻量规划、检索与复查阶段的受限 ReAct。简单查询或局部替换无需完整长计划。内部策略、候选和草稿迭代不是方案版本，成功修改提交才追加一个版本。
24. **受控能力**：Agent 可列出素材、读媒体信息、搜索证据、读邻近上下文、预算内复查画面、读方案和任务状态。方案校验及提交是必经受控节点。预览和导出只接收明确用户意图进入业务授权流程。模型不能直接操作数据库、消息队列、对象存储、任意地址或 shell，也不能自选用户身份、提升权限或重置预算。
25. **行为与退出**：理解硬约束并保留；无法合理确定的关键缺失或冲突才澄清，低影响选项默认并说明。主题可确定而未说明时长时，可说明采用 30–45 秒初稿，不覆盖已有时长。先复用证据，再有限改写、补查、比较和自检。目标完成、无新证据、无法满足约束、等待澄清、预算耗尽或取消时停止。选段追求观点完整，局部修改保留无关部分，证据不足诚实说明；模型自检不等于业务校验或艺术质量证明。
26. **持久接纳与固定上下文**：消息、逻辑轮次、理解任务和 Outbox 同事务接纳，重复发送返回同一结果。对话任务覆盖查询、生成、修改和澄清；理解结果经业务校验后保存关联的固定执行请求，再分配方案和取得编辑权，不改写已接纳任务输入。公开聊天追加保留，模型读取有界历史、摘要、按需求隔离的简报、固定对象及相关证据，精确条件仍可追溯原消息。
27. **澄清与重试**：问题有明确身份，原输入框回答经系统理解后保存与原问题的明确关联。等待输入保存运行状态，释放执行槽和方案编辑权但保留会话活动关系；含糊回答先澄清，恢复时重验目标与权限，改变基准时建立关联的新任务。自然语言明确开始新需求结束旧等待。自动重试使用新执行尝试，终态失败后的用户重试关联原需求，复用已有解析、执行请求和结果，不重复用户消息和已提交版本。
28. **公开事件与恢复**：后端持久化关键公开事件和草稿快照，再推送 SSE；一致快照、提交顺序游标及重放支持刷新、断线与重复事件。过期游标要求重载快照；旧执行尝试的草稿不能拼入新回复。页面断开不取消任务，取消必须显式发起。只展示进度、依据及结果，不向用户泄露供应商内部推理、私有路径或工具凭证。
29. **工作区**：素材、对话、播放器/结构化结果三部分，窄屏用页签组织。点击“新聊天”建立会话并先发送简短欢迎语、说明当前可用素材范围，默认一个聊天输入框，需求类型和证据来源由系统选择；制作／澄清表单及手动操作可选。证据卡可定位播放，问题卡对应待答问题，方案卡对应明确版本；输入支持明确对象引用。查看状态与运行输入分开，完整历史分页展示，需求简报按需求隔离并可自然语言纠正。

### 渲染、保留与成本

30. **最小剪辑集合**：支持选段、调整起止时间、重排、硬切、原声及自动字幕。画幅 16:9 或 9:16，等比例缩放留边；正式输出 MP4、H.264 视频、AAC 音频，720p 或 1080p。无音轨素材按统一输出策略处理，保证组合可播放；中文字体和字幕渲染必须真实验证。
31. **受控渲染**：后端校验素材归属、有效性、片段范围、输出数量/规格、字幕映射和硬约束。Java Worker 把方案编译为受控 FFmpeg 参数，不执行模型脚本；尝试使用独立工作区与对象范围，实际验证可播放性、时长、画幅及音轨后发布产物。
32. **可重建预览**：按版本、成片定义、实际预览规格及渲染规则复用产物/任务，依赖指纹纳入必要校验。初始每项目 2 GB 预览缓存、7 天未访问可清理，均可配置；GB 表示 10⁹ 字节。正在生成或播放的文件跳过清理，删除后不返回旧链接，可按需重建；不自动为所有版本生成预览。
33. **引用与文件保留**：全部方案历史保留，任何历史版本引用的源素材不能直接彻底删除，可隐藏。证据、时间映射、必要模型响应和分析版本随素材保留并保护引用。普通派生音频/帧是独立容量的可重建缓存，关键佐证帧保留或可可靠复现；它们不直接沿用预览期限。正式成片只由用户明确删除，下载不删除。
34. **有界开销**：记录模型用途、提供方、实际报告用量及估算费用，无实际用量则明确估算；限制调用、步骤、耗时、窗口、采样量和数据量，设置可配置预警。自动补查须先取得可撤回的项目授权，每个制作需求累计最多 4 次新增视觉调用，跨消息、修改、恢复和关联重试共享；更多调用或完整分析先说明并另行取得明确批准。预警不构成授权或金额硬上限；首版没有固定月预算或未经实测的低成本承诺，重排、预览和渲染复用已有分析。

### 任务与一致性

35. **Outbox 与至少一次通知**：任务与待发送事件同一 PostgreSQL 事务保存，确认 Broker 接收后标记发送。执行者经内部认证 API 原子领取持久执行权，再 ACK；执行启动中断由数据库状态和执行器恢复机制处理，ACK 不代表任务成功。重复通知不能启动重复执行进程或发布重复结果。
36. **执行尝试与取消**：心跳、租约、尝试标识和提交资格限制结果发布。过期尝试不能覆盖新尝试、释放别人的锁或覆盖终态；失败/取消/恢复释放正确占用。取消与完成原子竞争，本地进程确认停止后清理临时文件，不删除输入和已有成果；外部模型能否停止及费用由提供方决定。
37. **跨系统恢复与有限重试**：分别处理数据库、队列、对象文件、索引和模型的成功边界，结果回报幂等并核对原尝试及请求内容；重复回报可返回既有提交。异步模型保存提供方任务身份，超时先查询已有执行，再决定重试。不能承诺外部调用恰好一次或完全避免重复费用；无效素材/方案和不可满足条件不无限重试。

## Testing Decisions

### 测试边界与通过原则

1. **优先最高用户边界**：主验收通过浏览器操作与业务 HTTP API，观察消息、证据、版本、权限、任务和实际可播放文件。测试外部行为与不变量，不断言私有方法、提示词原文、内部节点名称或某次模型措辞。
2. **已有基线**：沿用已实现的应用测试与已确认协议、功能和故障验收，真实运行记录见 verification/ 与 implementation-status.md；新增统一对话场景仍须实施后验证，不把设计确认当作测试通过，不为每个内部模块新增独立验收入口。
3. **必要真实边界**：对上传与对象清理、PostgreSQL 事务/并发、RabbitMQ 重复派发、Qdrant 索引发布、模型协议和 FFmpeg 输出做集成验证。单元测试仅补充确定性的时间计算、方案校验等关键规则；最终闭环不能只靠模拟依赖通过。
4. **确定性与智能分开**：权限、版本、授权、幂等和格式是必须通过的不变量。内容质量使用人工标注的小型固定素材与保留查询，不能以模型自评或模型生成的标准答案替代人工依据；随机措辞不是失败，虚构来源、违反硬约束和破坏局部修改范围是失败。
5. **待实测阈值明确记录**：记录 Recall@K、排序质量、时间定位误差、观点完整性、耗时、资源峰值与调用费用；以代表样本建立基线并固定配置，不编造尚未确认的速度、费用或准确率目标。必须报告未验证条件。

### 用户行为验收矩阵

下列条件共同构成首版完成标准。每项采用可核查素材或故障注入，不要求固定模型回答文本。

| ID | 操作与条件 | 必须可观察的结果 |
| --- | --- | --- |
| AC-01 | 两账号各自创建项目，再尝试读取对方素材、消息、证据、任务、对象链接和导出 | 正常操作只返回自己项目内容；对方内容不可读写，各检索通道也不泄漏 |
| AC-02 | 上传有效视频，观察传输、验证、分析三个阶段 | 传输完成不误报全部就绪；验证通过可播放；分阶段显示分析/索引能力 |
| AC-03 | 上传中断网、暂停、授权过期后继续 | 已成功分片保留，失败片有限重试或重新授权，不重新传完整文件 |
| AC-04 | 上传中刷新，重选原文件；再选择同名不同内容文件 | 原文件可恢复；不同内容不能续接；双标签页不竞争续写 |
| AC-05 | 丢失创建/完成响应、重复完成，取消与完成竞争，取消时仍有在途分片 | 恢复后至多发布一份有效素材；残留可核对清理，实际未释放字节仍计入占用 |
| AC-06 | 上传损坏、不可解码、超时长/字节限制素材；并发上传与低空间 | 不发布无效素材，给出可解释原因；空间/名额预留阻止绕过限制；24 小时过期行为可配置验证 |
| AC-07 | 语音就绪而视觉失败，随后恢复视觉；另令索引同步失败 | 语音可先查询；仅失败阶段恢复；索引重建不重新进行成功的 ASR/VLM 调用 |
| AC-08 | 查询标注的中文主题、专名、数字和短语，对比语义/BM25/融合 | 返回可核查来源和时间，记录各通道及融合质量；原文特殊字符被正确处理 |

## Out of Scope

首版明确不做以下能力；保留扩展性不等于首版实现它们：

1. 团队协作、项目分享、成员权限、多人同时编辑同一方案及并发编辑合并。
2. 完整专业非线性剪辑时间线、多轨复杂编辑、任意效果/转场脚本、音乐节奏编排、配乐、生成配音、智能主体裁切和复杂调色。
3. 每帧全量视觉/OCR 分析、保证找出所有短暂画面或全部文字、直接图像/视频向量作为必选检索能力、预先增加必选精排模型或 Elasticsearch/OpenSearch。
4. 保证专业剪辑师审美、自动审片迭代到满意、Agent 自主反复预览或正式渲染、绕过版本确认或明确导出授权。
5. 无边界自主 Agent、首版多自主 Agent 角色体系、任意 shell/数据库/对象存储工具权限、自动无上限补查或整段重新付费分析。
6. 本机模型训练或推理、模型训练平台、独立部署模型网关、未经验证的 GPU 加速、生产级分布式集群和高并发规模指标。
7. 成功回复的任意重新生成与历史消息编辑回放分支；独立探索使用新制作会话，方案版本仍支持从旧版继续修改。
8. 自动为每个方案版本生成预览、永久保留所有低清预览、自动清理正式成片或历史引用的原始素材。
9. 独立 tus/自建文件拼接续传服务、浏览器刷新后无须重新授权/选文件的跨浏览器保证。
10. 外部模型调用和收费恰好一次保证、固定低费用承诺、尚未测量的延迟/吞吐/准确率 SLA、固定月预算与计费商业化系统。
11. 与上述不在范围能力对应的复杂管理后台或产品流程。需要更多资源/费用时使用当前明确预算与用户选择，不提前扩张产品范围。
