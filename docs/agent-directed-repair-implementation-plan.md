## 执行方式

按阶段顺序实施，每阶段先完成与当前变更对应的行为测试，再修改实现，验证完成后更新阶段记录。不要将写完代码、单个函数测试通过或文档生成视为阶段验收。

主验收入口复用 Agent.send、prepare_run、execute_run 与现有恢复入口；脚本模型与受控工具驱动真实图。Java 完整校验使用已有接口集成测试，浏览器只验证当前有效链路。不新增生产测试入口。

只改本计划列出的职责。既有用户未提交改动保留；只追加文档索引及本次必要修改，不清理其他文档或测试数据。确有阻碍时才定向清理测试状态，不默认删除整个数据库。

## 阶段 1：故障样本与测试基线

工作：

1. 将现场三版草稿、要求、必要原始观察证据和校验反馈提取成最小固定样本；不依赖本机历史数据库存活。
2. 经现有 Agent 入口重现格式错误后出现 32.02 → 38.74 → 32.02 秒草稿并停止的行为。
3. 固定成功对照：移除历史回顾后 19.38 秒，保留片段顺序、边界与引用。
4. 建立待改行为的失败测试；后续阶段逐步转绿，不将旧错误预期固化为最终产品要求。

涉及：现有真实制作、草稿修正、制作会话运行测试及最小 fixture。

完成门槛：可在无网络、无真实付费调用条件下稳定复现；测试能区分原始问题、预算停止与合法草稿；样本有来源说明且无凭据。

## 阶段 2：请求理解协议

工作：

1. 修改 UNDERSTAND 提示与字段描述，明确可空标量与列表语义。
2. 在 Understanding 模型边界将 output_durations 的 null 规范化为空列表；其他错误继续快速失败。
3. 验证未修改、全体时长修改、逐条时长修改以及非法字段类型，不改变条件合并语义。

主要文件：

- [prompts.py](../agent-service/agent_service/prompts.py)
- [state.py](../agent-service/agent_service/runtime/state.py)
- [request.py](../agent-service/agent_service/runtime/nodes/request.py)（仅在解析衔接需要时修改）

验证：请求理解与制作会话入口测试；确认该 null 输入不触发额外模型调用，原有条件仍保持。此阶段不更换模型适配方式。

完成门槛：目标协议冲突消除，非法输入不会被宽泛吞掉，相关理解与合并回归通过。

## 阶段 3：删除候选与定向修正

工作：

1. 在草稿修正模块增加失败输出级删除单片段候选，沿用边界候选。
2. 生成草稿哈希、output_key、被删片段与前后时长、语义上下文；遵循 Spec 的排序与数量上限。
3. 将候选与错误方向送入现有模型上下文，要求模型作语义取舍并重交完整草稿。
4. 明确无候选不等于无解；缺少读取时给出精确范围，允许合法补读恢复。

主要文件：

- [draft_repair.py](../agent-service/agent_service/runtime/draft_repair.py)
- [calls.py](../agent-service/agent_service/runtime/calls.py)
- [prompts.py](../agent-service/agent_service/prompts.py)

验证：候选模块测试与 Agent 完整制作场景；覆盖 19.38 秒候选、多输出保护、只剩一片段、删除后仍超长或过短、过期候选以及有效补读后相同稿重交。

完成门槛：失败样本能获得有效删段选项；脚本模型选择后仍经完整校验才进入 DRAFT_READY；模型未选择时程序不擅自删段。

## 阶段 4：预算与进展

工作：

1. 按 Spec 引入 format_repairs、business_repairs，repairs 只汇总；修改所有现有读写点及限制构造处，避免残留共享上限。
2. 理解和动作结构错误计格式预算；已解析动作业务错误与草稿错误计业务预算；不改变基础设施失败与未知提交处理。
3. 明确每次失败唯一扣额节点，停止后结果核对不二次扣额。
4. 将草稿停滞与读取进展分开；实现同需求下的错误消除、时长差额改善及新问题判定。
5. 提供分类余量，保留模型、工具、时间整体硬上限。

主要文件：

- [state.py](../agent-service/agent_service/runtime/state.py)
- [policy.py](../agent-service/agent_service/runtime/policy.py)
- [request.py](../agent-service/agent_service/runtime/nodes/request.py)
- [decision.py](../agent-service/agent_service/runtime/nodes/decision.py)
- [tools.py](../agent-service/agent_service/runtime/nodes/tools.py)
- [calls.py](../agent-service/agent_service/runtime/calls.py)
- Config 与测试中构造 Limits 的调用处（仅同步新字段）

验证：经 Agent 入口验证分类上限、零额度、自始无效动作、整体调用先耗尽、首次失败基线、38.74 → 25 秒改善、32.02 → 38.74 秒恶化、新问题出现、插入补读仍停滞、需求改变及问题截断。

完成门槛：格式消耗不挤占业务机会；循环有界；错误数值变化不再被当成新错误身份；单个问题改善不能掩盖其他问题恶化。

## 阶段 5：结果发布与新任务恢复

工作：

1. 基于有效的最新校验和停止原因生成具体 content 与 Failure，不额外调用模型。
2. 接通理解到执行、补答、重启、重投的分类预算与进展状态，维护原调用回执和执行身份。
3. 验证 Worker 透传，Java 接收、存储并发布失败消息，前端展示具体条件。
4. 验证 INCOMPLETE 不携带可接受草稿绑定；DRAFT_READY 继续要求当前哈希对应的完整校验通过。
5. 更新运行模块说明中的预算含义与诊断字段。按新结构直接实施，不加入旧状态 fallback。

主要文件：

- [result.py](../agent-service/agent_service/runtime/nodes/result.py)
- [conversation.py](../agent-service/agent_service/runtime/conversation.py)
- [runner.py](../agent-service/agent_service/runtime/runner.py)

验证：新版本创建任务后暂停、重启、补答和重投；确认预算不归零、成功回执复用、未知付费结果不自动重付。运行现有 Worker 公共结果、Java AgentRun 契约与集成测试。

完成门槛：错误内容可到达浏览器；不会误报条件无解或草稿可接受；新任务恢复语义正确。Java/前端如确需改动，先记录契约缺口，保持修改最小。

## 阶段 6：综合交付

工作与顺序：

1. 运行涉及模块回归，再执行一次 Python 完整非付费回归；预算和状态是共享机制，范围覆盖 QUERY、DISCUSS、DRAFT、等待与恢复。
2. 运行相关 Java AgentRun、草稿校验、制作会话生命周期集成测试；如修改 Java 实现，补充相应编译与打包。
3. 更新本地运行服务，使用当前浏览器入口验证新任务成功与失败展示，以及草稿预览/确认入口资格。前端若有实现改动，再跑类型检查与构建。
4. 复用已分析素材进行单独真实模型验收：原始确认请求与明确选段请求各 3 次独立执行，不并入默认自动测试。记录每次完整结果，若出现失败则保留轨迹分析，不通过临时扩大预算凑通过。
5. 汇总确定性测试与真实模型验收，不用少量样本宣称统计成功率已改善。真实验收未执行时标明未执行，不写成完成。

完成门槛：确定性关键场景全部通过；当前页面正确展示结果；真实调用结果与局限已报告，出现未解释的新故障则阶段不关闭。未通过草稿不能被接受，合法草稿仍遵守用户接受后保存版本的边界。
