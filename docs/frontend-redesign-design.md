# 前端工作区重构设计

日期：2026-10-16（Asia/Shanghai）。状态：用户已认可重构方向，本轮整理设计与实施计划；尚未启动代码实施。实施顺序、逐步验收和回归要求见[分步实施计划](frontend-redesign-implementation-plan.md)。

## 目标与设计原则

面向使用视频素材进行问答和剪辑的普通创作者，建立以对话推进制作、以视频验证结果的工作区。用户无需理解内部标识、分析流水线或检索参数，即可完成素材导入、问答、草稿调整、预览、确认、正式导出和下载。

界面应持续回答四个问题：当前处理什么对象，系统正在做什么，结果是否符合要求，下一步可以做什么。信息是否常驻，由它能否帮助判断结果、采取行动或理解费用与恢复决定。

遵循根 [AGENTS.md](../AGENTS.md)：从用户任务出发，复用现有能力，只增加本次重构所需的最小展示与交互，不扩大业务范围。继续使用 Vue 3、TypeScript、Vite 和原生 CSS，不迁移框架或样式库。

## 范围和业务边界

### 本阶段包含

- 登录与项目入口的视觉一致性、项目内导航和窄屏布局。
- 素材列表、上传状态、分析状态、内容查找和原视频核查的组织。
- 聊天、澄清、引用、草稿摘要、聊天内预览和确认操作的展示。
- 已确认方案、版本与输出选择、正式导出、播放、下载和成片删除的组织。
- 用量、费用提示、现有高级维护能力的信息分层。
- 加载、空、失败、停止、只读、产物失效状态及键盘可访问性。

### 本阶段不包含

时间线编辑器、手工拖拽剪辑、已冻结版本派生编辑、恢复历史草稿编辑、批量预览或导出、自然语言确认或媒体执行、素材文件夹与标签系统、团队协作、新管理后台、新权限体系、模型或检索算法调整。

不为本次 UI 重构新建缩略图流水线、摘要模型、计费系统、通用播放器框架或全局状态框架。已有数据足以完成展示时不增加后端字段；发现契约缺口先记录具体场景和影响，不用虚构内容填补。

### 继续生效的生命周期规则

本设计沿用[当前功能](current-features.md)及[对话生命周期设计](conversation-lifecycle-browser-design.md)的 CL-Q1～CL-Q13。旧路线中关于自然语言媒体操作、派生编辑、批量渲染和历史三列布局的描述，不作为本次重构的新增需求。

| 规则 | 界面要求 |
| --- | --- |
| 问答或讨论不自动生成方案 | 不设置必须创建制作才能聊天的流程 |
| 当前最新且具有后端操作资格的草稿才可预览或确认 | 沿用快照的 canPreviewDraft、canAcceptDraft，不靠“任务结束”自行恢复资格 |
| 未确认也可预览，预览不是确认前提 | 两个操作独立开放，不能设置必须先预览的门槛 |
| 确认整体接受所有输出，原子创建并确认不可变方案版本 | 按钮明确写“确认全部输出”；提示确认后当前草稿不能继续编辑 |
| 正式导出须单独明确请求 | 确认成功后提示“前往作品导出”，不自动开始渲染 |
| 多输出每次预览或导出一条 | 单输出直接操作，多输出操作前明确选中一条；确认仍覆盖整份草稿 |
| 历史草稿只读，已冻结制作不支持派生编辑 | 允许查看和引用讨论，不提供“恢复编辑”或“修改为 V2”入口 |
| Agent、预览、导出停止范围独立 | 分别命名“停止回复”“停止预览”“停止导出”，不用一个全局停止按钮 |
| 切换、关闭和刷新页面不取消后台任务 | 展示切换与取消分离，刷新从权威快照恢复 |
| 只有可恢复的失败允许重试 | 沿用原输入和既有幂等键；UNKNOWN 付费提交或预算耗尽不提供强制重试 |
| 会话素材范围、制作 scope 与本轮引用含义不同 | 引用标签不改变固定制作范围，新上传或新分析不自动加入既有制作 |

## 信息架构与导航

### 项目入口

项目列表保留项目名称、创建项目和打开项目能力。先使用现有字段，不编造封面、更新时间或作品数量。创建表单集中在创建操作处；空列表直接引导创建。

项目顶部合并品牌、返回项目列表、项目名称、主导航、用量和账户入口，减少重复页头。退出登录收在账户入口。用量详情不再插入并挤压整个工作区。

### 项目内三个主视图

| 主视图 | 主要任务 | 相关内容 |
| --- | --- | --- |
| 素材 | 导入、浏览、查找内容与回看原片 | 上传队列、素材状态、内容查询、素材详情 |
| 制作 | 问答、讨论、澄清、调整草稿、预览与确认 | 聊天、当前制作摘要、引用、当前草稿和预览 |
| 作品 | 查看已确认方案，导出与管理成片 | 版本、输出、导出记录、播放器、下载和删除 |

“作品”包含已确认方案和正式成片；已确认但尚未导出的条目明确标为“待导出”，不能称为已生成的视频。

首次进入且没有素材的项目默认展示素材空状态；其余项目优先恢复上次有效主视图。仅持久化主视图等必要浏览偏好，已有聊天选择和方案浏览位置继续沿用现有恢复机制。刷新不承诺保存尚未发送的输入；同项目主视图切换不得丢失该输入和引用。

### 制作视图线框

```text
← 我的项目 / 项目名称        素材  制作  作品         用量  账户
───────────────────────────────────────────────────────────
当前聊天 ▾       新聊天       │ 当前草稿 / 正在查看的原视频
                             │
对话记录                     │           视频预览
澄清问题                     │
草稿摘要与历史结果           │ 输出标题 · 时长 · 画幅 · 字幕
                             │ 片段与字幕详情
本轮引用                     │
输入需求……             发送  │ 预览草稿       确认全部输出
```

对话保留草稿和预览的历史消息；右侧显示当前选中的草稿、预览或原视频。确认和预览操作集中在当前草稿详情，聊天草稿摘要提供“查看草稿”定位入口。窄屏将详情放在当前视图的预览页签中，确保草稿仍可从聊天到达。

同一份草稿仅有一个操作状态来源和一组操作入口，不能让聊天摘要和右侧面板各维护一份 busy、幂等键或可操作资格。历史预览按原来源播放，不随“当前草稿”切换而改变。

### 响应式规则

以 1366×768 桌面、768×1024 平板、390×844 手机作为验收视口。约 1024px 以下制作视图改为单栏“对话／预览”切换；具体断点按基线实屏调整并记录，不维护多套业务流程。

顶部主导航始终可到达。切换窄屏预览不清空输入或引用；从证据进入播放器后提供明确返回位置。主内容无横向溢出，长文件名与长消息可换行；局部数据表必要时独立滚动。

## 素材与内容查找

### 素材条目与上传

使用紧凑列表行组织文件名、已有时长、能力状态、播放和更多操作。没有时长时不填零；首轮不要求封面或缩略图。

上传中的文件在对应行展示真实传输进度、暂停、继续、取消；校验与媒体验证作为后续状态分别表达。上传完成并关联资产后合并展示，不能靠同名文件判定同一对象，沿用上传与素材已有身份关系。

暂停或失败条目保留恢复操作。刷新后需要重选原文件时提示原因和恢复期限；过期明确要求重新上传。取消上传与实际释放空间分别表达：“上传已取消，空间正在释放”，清理后再显示释放完成。

### 素材能力状态

默认回答用户能做什么，例如“可以播放，语音分析中”“语音已就绪，画面分析失败”。完整 MEDIA、ASR、VISION、EMBEDDING、INDEX 状态仍可在详情查看，但不合并成一个可能误导的“全部就绪”。

无音轨属于能力限制，不显示成系统故障。分析失败保留原因与允许的阶段重试；不得重新触发已成功阶段。用户主动补充画面分析和现有补查能力保留明确入口，并提示已有费用或预算信息。

### 内容查询与回看

查询框优先展示，来源类型和原文／语义方式收为筛选项。首轮保持现有查询参数与默认语义，不创建自动混合查询算法。结果显示素材名、原文或观察文本、时间位置、查看原视频与相关上下文。

覆盖详情按需展开；未命中时简明说明查找范围。稀疏画面分析、识别遗漏及模型时间戳的限制保留在相关结果旁，不能把“未找到”改写成“没有出现”。候选复查与扩大补查继续沿用现有明确授权和预算边界。

素材视图内查看原视频；制作中的证据核查使用制作右侧预览，保留聊天。两处复用现有原视频播放能力，不创建全局播放器服务。视频优先展示，编码、帧率、分析详情和精确秒数输入放在次级详情。

## 对话与草稿交互

聊天选择与新聊天合并在工具栏。没有聊天时提供明确的新建入口，不因切换视图偷偷创建会话或触发模型调用。

当前制作条件显示为简短摘要，完整要求按需展开。引用以素材名称、问题摘要或草稿标题显示为可移除标签；内部 ID 保留用于协议，不作为用户文案。

待澄清问题在输入区附近可见，沿用原输入框回答；独立问答不消费原问题。发送中提供真实执行阶段和停止入口，不伪造逐字输出或完成百分比。

输入区在制作视图内保持可达。中文输入法组词期间不能触发发送；保留明确发送按钮。使用快捷键时标注规则，支持换行。用户停留消息底部时新内容跟随，回看历史时显示新消息提示，不强行滚动。

草稿默认显示输出标题、时长、画幅、字幕、片段数量和摘要。素材 ID 映射为现有文件名；重名时借助片段时间和列表序号区分。片段时间以分秒阅读，精确切点详情保留小数；显示格式不改变 API 毫秒值和哈希。

当前草稿确认前明确说明覆盖的输出数量；确认成功后保留只读内容并提供“前往作品导出”。确认不新增第二次重复确认表单。修改期间、已封存或条件变化时给出具体禁用原因，不能只显示统一“不可用”。

同一预览请求依据 request、artifact 与消息引用的已有关系合并成一张状态卡：排队、生成中、成功播放、失败或失效。多个不同请求仍分别保留；不能仅按输出标题去重。历史来源使用“历史草稿预览”等名称，关联关系保留在内部。

## 作品与成片交互

作品视图先选择已确认方案，列表中展示可从现有内容取得的标题与状态。仅一个版本时直接查看，多版本保留版本选择，不新增版本比较器。切换查看对象不改变正在运行的导出来源。

选中方案后展示输出列表、播放器、来源版本及片段详情。多输出预览或导出前明确选择一条。导出清晰度在导出操作区选择，实际提交继续使用具体 revision、confirmation 和 output 身份。

| 当前状态 | 主要操作与反馈 |
| --- | --- |
| 已确认但尚无成片 | 导出成片，选择 720p 或 1080p |
| 排队或导出中 | 真实状态、停止导出；不重复提交 |
| 导出成功 | 播放、下载；更多操作中可删除成片文件 |
| 导出失败或停止 | 保留原因和记录，只开放既有契约支持的后续操作 |
| 文件失效或删除 | 明确文件不可用，不把记录成功误作当前可播放 |

导出历史按已有时间、清晰度和状态组织。历史方案若尚未确认，保留“确认当前版本”的既有能力；新聊天确认形成的版本不要求再次确认。

删除成片前说明对象与后果并取得明确确认；正在删除与已删除分别反馈。下载不触发删除，删除不影响原素材。

## 信息展示与诊断边界

| 信息层级 | 内容 | 位置 |
| --- | --- | --- |
| 默认展示 | 名称、时间、输出、版本、当前能力、可操作失败原因、相关费用风险 | 当前任务上下文 |
| 按需查看 | 编码、帧率、完整分析阶段、字幕、片段依据、查询覆盖、存储分类、估算依据 | 详情和用量面板 |
| 诊断与高级维护 | 制作及校验 ID、编辑代次、请求回执、原始报告、索引模型、向量维度、BM25 参数 | 项目次级“诊断与高级维护”入口内按功能组织 |

现有维护能力不删除，也不挂到播放器上。高级维护入口保留现有权限边界，进入不会自动执行重建、分析或模型调用。诊断仅展示现有允许公开的业务字段；凭据、私有路径、供应商内部推理不进入界面。

用量入口默认展示已用存储、估算费用、未知费用与预警；明细和原始回执分层展开。未知费用不能当零计入展示，待清理占用不能当已释放。预警仅提示、不阻止执行，不称为预算上限。

错误先说明失败事项、影响和可行下一步，再提供技术详情。只能依据已有错误信息映射，未识别错误保留真实原因；不得吞掉错误或统一冒充“网络不稳定”。如现有 API 无法安全区分错误，列入契约缺口，不以全量原始响应作为诊断内容。

## 视觉与可访问性

保留灰绿方向，以中性浅灰背景、清晰内容表面和低饱和深绿构成主层级。建议起始色值为背景 #F3F5F0、正文 #15251F、主操作 #245C45；最终按实屏和对比度验收调整。状态色承担错误与警告，不用于装饰。

中文正文采用现有系统字体栈，约 14～16px，正文行高约 1.6；标题使用中等与半粗字重。时间和用量启用等宽数字。首轮不引入远程字体，避免为字体替换新增依赖和加载过程。

间距使用少量一致尺度，例如 4、8、12、16、24、32px；以留白与分隔线组织内容，减少嵌套卡片。视频画布可深色，其他区域保持一致色调。原视频、低清预览、正式成片均显示对象名称与来源。

按钮具备 hover、pressed、focus-visible 状态；主操作视觉突出，引用和查看详情降低权重，危险操作不与下载并列同色。交互目标原则上不小于 44×44px。短过渡约 150～200ms，仅使用 transform、opacity 等必要反馈，并尊重减少动态效果偏好。

内容加载可使用与布局对应的简单骨架；长任务显示真实阶段。空状态提供一项明确行动。局部错误就近展示，状态用文字和语义标记表达，不只依靠颜色。

主导航使用可访问语义和当前项标识；页签支持键盘切换，隐藏内容不得保留可聚焦控件。提供跳至主内容入口，输入有明确标签，错误与状态可被辅助技术感知。正文对比度目标至少 4.5:1，大文字及必要控件边界至少 3:1。

## 实现职责与最小约束

| 现有模块 | 重构后职责 |
| --- | --- |
| App | 登录、账户、项目外壳与基础视觉规则 |
| ProjectWorkspace | 项目导航、当前主视图、选中的查看对象和视图间定位 |
| UploadPanel、AssetLibrary、AnalysisStatus、SpeechSearch、InspectionPanel | 素材上传与列表、能力状态、查询和现有补查 |
| ConversationPanel、DraftCard | 会话和引用、草稿历史、当前草稿操作及其绑定 |
| MediaPlayer、ArtifactPlayer | 现有原视频与产物播放、签名续期和播放位置恢复 |
| PlanPanel | 已确认方案、版本、输出、正式导出与历史 |
| UsagePanel | 用量摘要、明细与预警配置 |

可把基础 CSS 迁入单个样式文件，并按明确重复职责拆分必要展示组件；不为一次性展示创建工具类或通用容器体系。

接口、幂等键、哈希、SSE／快照、上传并发与恢复逻辑默认保持不变。视图切换优先保留有状态业务组件，按项目身份隔离；项目切换或退出登录时按现有生命周期清理，不能泄漏前一项目的消息、播放链接和引用。

播放与草稿操作继续分别归属现有组件，通过窄接口传递选中对象和动作。不能为了双栏展示而复制同一份任务轮询、快照订阅或操作控制器。刷新恢复以服务端身份为准，浏览器偏好不能恢复已失效的操作资格。

## 阶段成功标准

1. 用户无需接触内部标识或索引配置，能够完成导入到下载的当前有效流程。
2. 素材、制作、作品可直接到达，制作主视图保持对话与视频的阅读空间，窄屏无主内容横向溢出。
3. 原片、草稿预览、历史预览和正式成片有明确来源，确认与导出作用对象清楚。
4. 当前业务能力和生命周期边界完整保留，导航不会新增请求、重置幂等身份或取消任务。
5. 部分分析失败、待澄清、停止、只读、产物失效、UNKNOWN 和预算耗尽均有准确反馈及允许的操作。
6. 同项目视图切换保留输入和引用，刷新恢复权威消息、当前草稿及独立媒体任务；跨项目和退出登录无状态串用。
7. 桌面、平板、手机及键盘主要操作验收通过，视觉审查完成必要修正。
8. 按[实施计划](frontend-redesign-implementation-plan.md)完成逐步定向回归、阶段完整非付费回归及验证记录；人工音画和付费验收单独说明。
