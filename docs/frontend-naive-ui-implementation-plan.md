# 前端 Naive UI 改造实现计划

日期：2026-10-30（Asia/Shanghai）。状态：阶段 1～5 完成，受控浏览器验收通过。需求基线：[本轮 Spec](frontend-naive-ui-spec.md)。用户已确认浏览器为主要测试边界，真实付费模型不作为默认验收。

## 执行原则与依赖

执行顺序：阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5。各阶段验收通过再进入下一阶段。本计划不要求并行代理，不自动发布 Issue、提交代码或部署。

本轮仅前端改造；保留上传、媒体权限、证据时间、草稿生命周期及后端任务状态契约。接口缺口先记录，不用新增后端能力掩盖布局问题。上一轮重构已完成的历史记录不作为本轮通过证明。

## 阶段 1：基线、主题和组件接入

完成记录：[阶段 1 验证](verification/frontend-naive-ui-stage1.md)。

### 工作

- 核对当前有效入口、领域术语和冻结版本约束，记录浏览器现状与依赖体积。
- 在 frontend/package.json 及现有锁文件加入经兼容性核对的 Naive UI；入口 App.vue、main.ts 配置必要主题与上下文。
- 调整 style.css 的全局按钮、输入、表单和间距规则，防止影响库组件；定义正文、辅助文字、按钮与图标尺寸。
- 先替换登录表单、新建项目弹窗与账户菜单作为小范围集成验证，不一次替换全部页面。
- 盘点 frontend/e2e 中测试的有效入口、受控接口/真实服务、是否付费；复用 frontend-redesign-baseline 与 fixtures/current-frontend。明确未适配旧导航的测试不能直接列为通过门槛。

### 验收

- UI-01：登录、注册、账户菜单与新建项目功能保持；处理状态、错误与禁用反馈清晰。
- UI-02：全局 CSS 不污染新组件；页面不存在两套互相冲突的主按钮规范。
- UI-03：新建项目弹窗支持键盘操作、Escape 与焦点恢复。
- UI-04：三视口现状及改后截图、测试分类表、构建体积变化有记录。

### 检查

运行对应受控浏览器场景及 npm run build（包含 vue-tsc 与 Vite 构建）。记录登录真实服务联调是否运行，不把受控结果描述成后端验证。

## 阶段 2：原片回看与可定位证据（P0）

完成记录：[阶段 2 验证](verification/frontend-naive-ui-stage2.md)。

### 工作

- 修改 MediaPlayer.vue 与 ProjectWorkspace.vue 的媒体弹层约束，实现桌面双区域、窄屏上下布局；播放器和证据浏览区域不随全部证据无限增长。
- 证据加入数量、关键词筛选、20 条分页、统一时间列、正文列及定位操作；长原文展开/收起，原文提要默认折叠。
- 处理选中高亮、切换素材清理、筛选回第一页、刷新保持有效状态，以及加载/失败/空列表/无匹配状态。
- 保留带起止时间的外部播放入口、权限续期和媒体播放逻辑；不将展示时间字符串用于定位。
- 在浏览器测试中使用确定性证据接口与已有本地视频，不依赖真实模型生成证据。

### 验收

- UI-05：0、1、20、21、200 条证据分别正确呈现；每页不超过 20 条，仅多页显示分页，分页可遍历全部数据。
- UI-06：关键词覆盖原始全部证据；匹配计数正确，清空恢复，筛选与切换素材回第一页；后台刷新不会无故重置用户位置。
- UI-07：长原文可完整展开；长文件名不挤掉操作；摘要和原文有明确区别。
- UI-08：点击目标证据后视频实际定位到原始时间附近并显示选中反馈；翻页、筛选、展开不触发播放；外部时间入口保持有效。
- UI-09：三视口无页面横向溢出，所有操作可达；大量证据不会把播放器推离可用浏览区域。
- UI-10：失败有重试入口，零证据与零匹配文案不同；切换素材不遗留旧内容。

### 检查

运行新增证据浏览场景、当前有效的原片回看与带时间引用场景，以及 npm run build。定位断言用本地媒体的 currentTime 与合理时间容差，不依赖截图判断。

## 阶段 3：素材抽屉、上传、检索与引用（P0/P1）

完成记录：[阶段 3 验证](verification/frontend-naive-ui-stage3.md)。

### 工作

- AssetDrawer.vue 使用统一 Drawer 与 Tabs，保持素材/查找两个入口及嵌套原片回看。
- AssetLibrary.vue 统一素材行、状态标签、加载/空/失败状态及更多操作菜单。
- UploadPanel.vue 统一任务行和进度组件；保留 uploads.ts 的上传职责及重选文件恢复语义，不接管默认上传请求。
- ConversationPanel.vue 使用可搜索多选与引用标签；不改变本轮引用与固定素材范围的区别。
- SpeechSearch.vue、InspectionPanel.vue 统一命中与观察的时间、正文和操作层级，邻近原文及观察帧按需展开收起；预算与覆盖说明保留。

### 验收

- UI-11：Tabs 可用方向键切换，焦点与选中状态一致；打开播放器后只由顶层弹层处理关闭，关闭后回到原触发位置。
- UI-12：长文件名、多素材及状态变化不破坏素材行；菜单展开不推高整行。
- UI-13：上传进度、暂停、恢复、取消及刷新后重选入口正确，网络语义与原分片上传一致；浏览 UI 不触发额外上传或分析。
- UI-14：引用可搜索、多选、移除且不修改制作范围；多引用不挤坏输入框。
- UI-15：检索仍明确显示候选数量而非全量总数；原片定位、邻近原文和观察帧可用；补查仍需明确触发，扩大范围与费用决定保留。

### 检查

运行当前有效的素材、上传状态、引用、检索和弹层受控测试及 npm run build。真实上传恢复验证依赖既有服务，单独记录；受控请求验证不代替对象存储联调。

## 阶段 4：产物组织与工作台布局（P0/P1）

完成记录：[阶段 4 验证](verification/frontend-naive-ui-stage4.md)。

### 工作

- PlanPanel.vue 按方案内容、效果预览、正式导出记录分区；保留当前方案/版本标识及任务实际来源。
- DraftCard.vue、DraftContent.vue 仅做必要的视觉衔接，保留草稿确认全部输出和历史只读语义。
- 集中当前主要操作，多输出预览与导出先明确选择一条；不增加必须先预览或重复确认的门槛。
- ProjectWorkspace.vue、WorkspaceRail.vue 调整桌面面板宽度控制与窄屏覆盖式导航；宽度约束保证对话可用，支持键盘调整，不新增持久化设置。

### 验收

- UI-16：多方案、多版本、多输出可识别；片段与字幕按需展开，主要操作不淹没在说明中。
- UI-17：接受草稿原子保存并确认全部输出，未确认草稿仍可预览，正式导出单独发起；不恢复冻结版本派生编辑。
- UI-18：切换版本不会更改已运行预览/导出的来源；停止回复、预览、导出各自独立；关闭面板不取消任务。
- UI-19：导出中、失败、已停止、产物失效与历史只读状态正确，不自行放开后端禁止的重试或操作。
- UI-20：桌面鼠标与键盘均可调宽且不挤坏主区；窄屏打开任一侧栏仍可完成选择、关闭与焦点返回。

### 检查

运行当前三栏生命周期、草稿预览/接受、多输出导出、版本来源与响应式场景及 npm run build。复用现有生产工作台与生命周期用例的有效断言，适配入口后再纳入回归。

- UI-23：本轮所有受影响、已适配当前入口的非付费浏览器测试通过，前端类型检查与生产构建通过，截图和行为验收记录可追溯。
