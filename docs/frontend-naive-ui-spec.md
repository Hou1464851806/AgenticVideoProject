# 前端 Naive UI 与证据浏览改造 Spec

日期：2026-10-30（Asia/Shanghai）。状态：实施完成，受控浏览器验收通过；测试边界已获用户确认。本轮仅落地本地文档，不发布 GitHub Issue。

## Problem Statement

当前工作台外壳已有统一配色，但素材、原片回看、方案与用量等内部区域仍大量依赖小字号段落、原生控件及按钮堆叠。用户难以辨认主要操作，复杂内容占用过多空间。

原片回看将全部语音原始观察证据渲染为不等宽的按钮，没有展示数量限制。长原文与时间混排，证据数量增加后页面持续增长，用户阅读证据时难以同时查看视频。手写标签页和弹层的键盘行为不完整。

本轮依据源码审查与用户反馈，不把源码推断视为浏览器实屏验收。当前技术栈为 Vue 3、TypeScript、Vite 与手写 CSS。

## Solution

使用 Naive UI 统一控件和基础交互，保留克制的黑白灰风格、对话驱动制作及既有业务能力。优先完成视频与证据联动、产物信息组织和弹层可访问性，再统一素材、上传、检索、引用和用量界面。

桌面原片回看采用视频与证据双区域，窄屏上下排列；证据可筛选、分页、展开全文和定位播放。其他复杂区域按用户任务分区，避免通过缩小字号容纳全部内容。

## User Stories

1. 作为创作者，我希望视频与证据能同时查看，以便核查识别内容。
2. 作为创作者，我希望知道证据总数及筛选后的数量，以便判断浏览范围。
3. 作为创作者，我希望每页最多显示 20 条证据，以便大量证据不会撑长整个页面。
4. 作为创作者，我希望按原文关键词筛选证据，以便快速找到相关内容。
5. 作为创作者，我希望时间、原文和操作分别对齐，以便快速扫描证据。
6. 作为创作者，我希望展开长原文，以便完整核查而不丢失内容。
7. 作为创作者，我希望点击定位后突出选中证据，以便确认当前核查对象。
8. 作为创作者，我希望切换素材后清除旧筛选和选中状态，以免混淆素材。
9. 作为创作者，我希望空证据、筛选无结果、加载中和读取失败分别说明，以便知道下一步。
10. 作为创作者，我希望素材摘要与原始观察证据分开，以免把摘要当作原文。
11. 作为创作者，我希望媒体参数和分析详情按需打开，以便优先观看视频。
12. 作为创作者，我希望清楚区分方案内容、效果预览和正式导出记录，以便选择正确操作。
13. 作为创作者，我希望切换方案版本时仍知道预览和导出的实际来源，以免误认结果。
14. 作为创作者，我希望多输出时明确选择一条预览或导出，以免执行错误对象。
15. 作为创作者，我希望确认草稿不会自动导出，以便自行决定执行与费用。
16. 作为创作者，我希望素材行有清晰状态和主要操作，以便快速播放或查看详情。
17. 作为创作者，我希望更多操作按需出现，以便列表保持稳定。
18. 作为创作者，我希望上传进度、暂停、恢复和取消排列一致，以便管理多个上传任务。
19. 作为创作者，我希望恢复上传时仍能重选原文件，以便保留已有分片进度。
20. 作为创作者，我希望搜索并多选本轮引用素材，以便素材较多时仍方便引用。
21. 作为创作者，我希望检索命中的邻近原文和观察帧按需展开，以便保持结果易读。
22. 作为创作者，我希望看到分析覆盖与补查费用边界，以便理解结果限制并决定是否补查。
23. 作为创作者，我希望桌面产物区域可调整宽度，以便阅读复杂方案。
24. 作为窄屏用户，我希望打开侧栏不会挤坏主内容，以便仍能阅读和操作。
25. 作为键盘用户，我希望标签页可用方向键切换、弹层约束焦点并在关闭后恢复焦点，以便完整操作。
26. 作为创作者，我希望正文与按钮足够清晰，以便无需放大页面也能使用。
27. 作为创作者，我希望关键用量、阈值和调用记录分区，以便了解成本与预警。
28. 作为创作者，我希望登录、账户菜单和表单反馈保持一致，以便理解成功、失败及处理中状态。
29. 作为创作者，我希望关闭面板或切换视图不会停止后台任务，以便自由浏览。
30. 作为创作者，我希望历史草稿只读及失败重试资格保持准确，以免界面提供无法执行的操作。

## Implementation Decisions

### 基础组件与设计规范

- Naive UI 为本轮唯一主组件库；不迁移 Vue，不另引入 Tailwind 或第二套 UI 库。实施时核对兼容版本并锁定依赖。
- 在应用入口统一主题及消息、弹层所需上下文；使用库的按钮、表单、输入、选择、标签、进度、菜单、Tabs、Modal、Drawer、分页与表格能力。原生 video 保留。
- 收窄全局元素选择器，取消按钮默认外边距及提交按钮自动成为主操作的规则；间距由容器负责，主次操作显式指定。
- 正文以 13–14px、辅助信息 12px、常规操作高度 32–36px 为设计起点，触控区域适当放大；最终以三视口验收为准。
- 仅为真实重复需求提取组件，不创建通用播放器框架或整套二次组件库。

### 原片回看与证据

- 宽屏播放器与证据并排；窄屏上下排列。证据独立限高滚动，播放器不随全部证据向下被推走；低高度屏幕须保证播放器与控件可访问。
- 当前原片回看只承诺已有语音 observations，不虚构画面证据字段。默认按起始时间升序，同时间保持原顺序。
- 客户端分页，每页 20 条；不超过一页时隐藏分页。原文关键词执行去除首尾空白后的不区分大小写子串匹配，不调用模型或语义检索。
- 显示原始总数、匹配数及当前页；空查询恢复全部。筛选或切换素材回第一页；同一素材后台数据刷新保留仍有效的页码和选择，页数减少时收敛到有效页。
- 每条证据分为时间、正文、定位播放操作。时间使用分秒，超过一小时显示时分秒；精确毫秒按需可见，实际定位始终使用原始毫秒值。
- 正文默认最多三行，确有溢出时提供展开与收起。选中高亮表示用户选择，不承诺随播放自动滚动或自动翻页。
- 翻页、筛选与展开不触发播放；点击定位沿用现有播放权限与起止边界语义。切换素材清除筛选、展开和选择；从外部带时间进入时保留该定位。
- 原文提要默认折叠；媒体详情和分析状态为次级内容。识别时间仅供核查的提示只展示一次。
- 无证据、无筛选匹配、加载失败与加载中独立呈现；失败可重试。前端分页只减少渲染量，不减少接口返回量。

### 工作台与业务面板

- 保留当前项目导航、对话和产物入口，不恢复历史文档中的退役导航。桌面产物面板可调整宽度，受主内容最小可用宽度约束；调整控件支持键盘。窄屏侧栏采用覆盖式面板，不并排挤压对话。无需跨刷新持久化宽度。
- 产物按方案内容、预览、导出记录分区，方案与版本选择保持可见；主要操作集中，片段与字幕按需展开。
- 当前查看版本与正在执行的预览、导出来源独立展示；多输出明确选一条预览或导出。接受草稿原子保存并确认版本，不新增重复确认门槛。
- 素材行统一文件名、状态及播放入口；次要操作进入菜单。当前无可靠字段的缩略图、时长不作为验收要求。
- 上传保留现有上传会话、分片、校验、暂停、恢复与取消逻辑，仅改展示；不得让组件库默认上传行为替换现有请求链路。
- 引用素材改为可搜索多选与已选标签，只改变本轮引用，不改变会话素材范围或制作范围。
- 检索命中与补查观察统一时间、来源、正文和操作层级；邻近原文与观察帧可展开收起。现有检索上限 20 条不伪装成全量结果，不为它增加虚假分页。
- 用量分为关键指标、阈值表单及调用记录，详细回执按需展开。菜单和错误反馈统一，关键失败保留就地提示，不只用短暂消息。
- 弹层支持 Escape、焦点约束及焦点恢复；嵌套播放层优先关闭最上层，背景不可交互；Tabs 有面板关联和键盘切换。

### 契约与业务不变量

不新增 API、数据库迁移、证据字段或全局状态框架。继续使用后端权限与快照判断操作资格，不用展示状态推断可确认、可预览或可重试。

遵循用户批准导出、可恢复上传和接受草稿后冻结方案版本的既有 ADR：预览不等于确认，确认不自动导出；历史草稿只读，冻结版本不新增派生编辑；停止回复、停止预览与停止导出独立；切换或关闭界面不取消任务；付费补查和扩大范围保留明确操作及费用说明。

## Testing Decisions

用户已确认：以现有 Playwright 浏览器测试为主，受控接口覆盖复杂状态，本地视频验证真实定位，补充类型检查与构建；付费模型调用不作为默认验收。

- 主要测试边界为现有 Playwright 浏览器页面，测试可见内容、键盘行为、网络操作语义与视频位置，不断言 Naive UI 内部 DOM 或组件私有状态。
- 优先沿用当前三栏工作台的受控接口浏览器基线与 current-frontend 夹具；旧 media、search、uploads、exports 等测试仅复用仍有效的业务断言，不能因文件存在就视为当前入口兼容。
- 覆盖原片回看、素材抽屉、对话引用、产物、用量和账户；不为每个按钮建立重复单元测试。
- 使用 0、1、20、21、200 条确定性证据，覆盖长原文、长文件名、匹配跨页、无匹配、数据刷新、素材切换和读取失败。
- 本地固定视频验证真实媒体加载和 currentTime 定位；定位误差以采样时机与视频时长设定容差，不能只验证点击发出了事件。前端媒体请求及接口受控，不触发真实付费分析。
- 视口至少 1366×768、768×1024、390×844；检查无横向溢出、内容可达、播放器与证据可用、面板切换及长文本布局。截图用于审查，不单独替代行为断言。
- 键盘覆盖 Tabs、菜单、分页、弹层、嵌套播放层和调整宽度；关闭后焦点回到有效触发位置。
- 制作回归覆盖未确认草稿可预览、接受全部输出、单条预览或导出、历史只读、切换版本不改变任务来源、停止范围独立。
- 前端类型检查与生产构建为各实现阶段门槛；真实服务与真实付费验收分别记录，默认不调用付费模型。

## Out of Scope

完整时间线编辑器、手动剪辑、自动跟随播放翻页、证据虚拟列表、服务端证据分页、新缩略图流水线、新语义检索、批量导出、新权限体系、冻结版本派生编辑、后端重构、自动部署、GitHub Issue 发布。

## Further Notes

本轮采用 Naive UI 的用户决定替代上一轮前端设计中“不迁移样式库”的约束；保留历史完成状态，不把本轮计划记为已实现。业务术语以[领域术语](../GLOSSARY.md)为准，阶段范围以[接受草稿后冻结版本 ADR](adr/0018-freeze-plan-revisions-after-draft-acceptance.md)为准，不因旧文档的长期能力描述扩大范围。
