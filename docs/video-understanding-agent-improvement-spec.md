# 视频理解与目标驱动 Agent 改进规格

整理日期：2026-10-14（Asia/Shanghai）。实施基准：`e65954da804b5ceab66e0d7e0be3493000847b30`。本规格合并当前对话中的视频理解、VideoRAG/VideoAgent 借鉴与统一编排改进；规格发布不表示功能已经实施或验收通过。

## Problem Statement

用户希望用自然语言询问视频内容，选择长视频中的亮点，组合多个视频，或修改已经生成的结果。系统应理解目标、自主获取必要信息、遇到关键歧义时追问，并以真实结果说明完成情况。

现有体验在信息访问、任务模式与完成判断之间存在断点：局部检索难以回答全片问题或保持上下文；通用画面描述可能遗漏当前问题需要的细节；讲话/混剪模式与固定编排限制妨碍表达更一般的需求；内部简报、候选、自检和业务接纳规则大量暴露给模型。用户也难以区分“找到片段”“保存方案”“启动渲染”和“得到可播放视频”。

项目需要在文本推理使用 DeepSeek Flash、ASR/VLM/Embedding 使用阿里云百炼对应模型、保留 LangGraph 和既有本机基础设施的条件下，提高有依据的问答、选段与编排能力，并能用固定样本说明质量、费用和延迟的取舍。单纯增加意图标签、提示词或研究模型依赖不能解决这些问题。

## Solution

用户继续通过同一个聊天入口表达目标。一个主要 Agent 根据实际信息缺口选择浏览、检索、阅读和定向观察，在业务限定的范围与预算内推进；必要澄清、等待分析和等待授权分别处理。

视频信息分成原始观察证据、带引用的时间窗口检索单元和可展开的全片内容目录。原始观察用于核查，检索单元用于定位，素材摘要与目录用于导航。已有内容优先复用，缺少必要画面信息时调用百炼 VLM 补查，追加保存新观察，供本轮和后续问题使用。

各种剪辑请求统一为成片定义中的有序源区间。Agent 选择内容与顺序，程序负责时长、字幕、范围、版本和渲染。对用户展示“剪辑要求”“剪辑草稿”“剪辑时间线”等直观名称；业务模型继续使用项目领域术语，保留方案历史和多输出结构。

系统按用户目标核对完成依据。问答需要可核查来源，方案需要实际保存版本，预览或导出需要成功且有效的产物。预览仍须用户明确请求；正式导出仍须具体方案版本确认与另行明确导出指令。没有获得完整授权或尚未得到产物时，报告已完成步骤与下一步，不宣称整项完成。

## User Stories

1. 作为项目用户，我希望直接用自然语言提出视频问题或制作目标，以便不必先选择查询、讲话或混剪模式。
2. 作为项目用户，我希望系统区分讨论想法与实际执行请求，以便讨论不会意外创建方案或产物。
3. 作为项目用户，我希望 Agent 从当前对话理解指代和条件，以便不用重复填写表单。
4. 作为项目用户，我希望看到简短的目标理解与已采用默认值，以便及时纠正误解。
5. 作为项目用户，我希望只有影响结果且无法合理推断的信息才被追问，以便交互能持续推进。
6. 作为项目用户，我希望明确要求和偏好被区分，以便“大约一分钟”不会被误当精确时长。
7. 作为项目用户，我希望后续修改只改变我提到的条件，以便原有要求得到保留。
8. 作为项目用户，我希望新制作需求不继承上一条的主题或禁用内容，以便不同工作不会混淆。
9. 作为项目用户，我希望素材范围、必须参与素材和禁止素材分别被理解，以便可选素材不会被强制全部使用。
10. 作为项目用户，我希望名称、版本或片段引用不唯一时得到澄清，以便操作正确对象。
11. 作为项目用户，我希望发送消息时的操作对象被固定，以便执行期间切换查看不会改变目标。
12. 作为项目用户，我希望在原输入框补答、取消或开始新需求，以便保持连续的对话体验。
13. 作为内容查询用户，我希望语音问题依据完整转写回答，以便知道视频实际说了什么。
14. 作为内容查询用户，我希望姓名、数字与原句得到保留，以便能核查精确内容。
15. 作为内容查询用户，我希望近义表达也能找到相关片段，以便无需使用视频原词。
16. 作为内容查询用户，我希望命中后能读取前后语句，以便代词、理由和完整观点不被孤立解释。
17. 作为内容查询用户，我希望同一时间范围能阅读语音、画面与可见文字，以便理解多来源内容。
18. 作为内容查询用户，我希望系统明确区分听到与看到的内容，以便语音提及不会被误报为画面出现。
19. 作为内容查询用户，我希望屏幕文字被单独记录并核查，以便参数、代码和数字有正确来源。
20. 作为内容查询用户，我希望浏览整段素材的内容分布，以便询问全片步骤、主题或亮点。
21. 作为内容查询用户，我希望内容目录可展开且能跳转来源，以便从概览进入具体内容。
22. 作为内容查询用户，我希望摘要仅作导航而非精确证据，以便模型概括不会替代原始内容。
23. 作为内容查询用户，我希望看到实际分析覆盖和未完成阶段，以便了解回答范围。
24. 作为内容查询用户，我希望检索未命中时得到范围与不确定性说明，以便不会误认为全片不存在目标。
25. 作为内容查询用户，我希望前后顺序依据实际时间判断，以便不能把相似描述当成时序关系。
26. 作为内容查询用户，我希望系统区分时间先后与因果推断，以便回答不过度解释画面。
27. 作为项目用户，我希望已完成语音分析在视觉失败时仍可使用，以便局部故障不阻塞全部工作。
28. 作为项目用户，我希望索引重建复用原始分析，以便不会为同一 ASR/VLM 结果重复付费。
29. 作为视觉查询用户，我希望初始描述不足时能针对问题检查原视频，以便获得遗漏的必要细节。
30. 作为视觉查询用户，我希望检查画面时明确传入检查目标，以便通用描述不会反复忽略所问内容。
31. 作为视觉查询用户，我希望状态变化问题能查看有序多帧，以便局部前后变化得到核查。
32. 作为视觉查询用户，我希望新观察附输入帧与真实时刻，以便能回到原素材检查。
33. 作为视觉查询用户，我希望模型明确无法判断项，以便有限输入不会被解释成完整观看。
34. 作为视觉查询用户，我希望对象标签不被当成稳定实例身份，以便不同杯子或人物不会被错误去重计数。
35. 作为项目用户，我希望新增付费补查前说明费用估算并取得项目授权，以便自主决定开销。
36. 作为项目用户，我希望同一需求跨消息、修改与恢复共享额度，以便不会反复获得新的默认补查次数。
37. 作为项目用户，我希望额度不足时先获知拟扩大范围与费用，以便明确选择是否增加分析。
38. 作为项目用户，我希望能撤回自动补查授权，以便阻止后续新增提交。
39. 作为项目用户，我希望已完成观察可以复用，以便后续问题更快且避免不必要调用。
40. 作为项目用户，我希望复用仍检查素材权限和版本，以便缓存不会泄漏或引用过期内容。
41. 作为项目用户，我希望不明确的付费调用先核对已有执行，以便系统不盲目重付。
42. 作为项目用户，我希望补查等待自动恢复 Agent，以便不用再发送“继续”。
43. 作为剪辑用户，我希望选亮点前浏览全片结构，以便结果不会只来自第一个关键词命中。
44. 作为剪辑用户，我希望 Agent 比较多个候选片段，以便选择更完整、相关且少重复的内容。
45. 作为剪辑用户，我希望默认亮点标准被说明，以便理解信息量、观点完整和重复程度的取舍。
46. 作为剪辑用户，我希望选段理由对应实际读取的内容，以便能核查为什么选这一段。
47. 作为剪辑用户，我希望讲话片段保留完整观点并检查词边界，以便不会截断句意或词语。
48. 作为剪辑用户，我希望视觉条件得到画面依据支持，以便“展示处理结果”不被语音讲解替代。
49. 作为剪辑用户，我希望多份素材统一编排为一条视频，以便组成教程或连贯叙事。
50. 作为剪辑用户，我希望自动整理时比较重复内容与衔接缺口，以便成片连贯且减少冗余。
51. 作为剪辑用户，我希望明确完整拼接时不擅自删改内容，以便系统执行我指定的机械组合。
52. 作为剪辑用户，我希望按明确要求使用指定素材顺序，以便编排符合我的结构。
53. 作为剪辑用户，我希望在支持的容量内表达素材交错，以便能将视频 A 的不同部分放在 B 前后。
54. 作为剪辑用户，我希望明确回放需求可作为任务策略处理，以便不会被默认去重永久禁止。
55. 作为剪辑用户，我希望长时间线受可解释容量控制，以便不会把短视频段数当作通用语义限制。
56. 作为剪辑用户，我希望草稿校验返回具体问题与实际时长，以便 Agent 能据此修正。
57. 作为剪辑用户，我希望正式保存时再次校验，以便检查后发生的竞争或条件变化不会发布无效版本。
58. 作为剪辑用户，我希望内部草稿迭代不产生方案历史，以便历史只记录实际保存结果。
59. 作为剪辑用户，我希望从历史版本继续修改并追加新版本，以便旧成果和修改来源都能保留。
60. 作为剪辑用户，我希望定向替换或精简仅改变允许范围，以便其他片段和输出保持稳定。
61. 作为剪辑用户，我希望未改片段由程序复用，以便模型不会重新描述并意外改变它们。
62. 作为剪辑用户，我希望字幕由原文与时间映射生成，以便不会出现模型编造字幕或重排后错位。
63. 作为剪辑用户，我希望无音轨素材能够按支持策略编排，以便不会被伪造语音或字幕。
64. 作为项目用户，我希望明确要求的查找、制作和预览连续推进，以便不用逐步重复发指令。
65. 作为项目用户，我希望预览绑定实际新版本，以便不会预览执行中后来切换到的对象。
66. 作为项目用户，我希望运行中的渲染显示进度而非“已完成”，以便了解真实状态。
67. 作为项目用户，我希望只有明确请求才生成预览，以便避免非预期处理。
68. 作为项目用户，我希望正式导出需要具体版本确认及明确指令，以便输出是我认可的结果。
69. 作为项目用户，我希望新版本不继承旧确认，以便修改后仍能决定是否导出。
70. 作为项目用户，我希望最终结果提供实际可用播放或下载入口，以便取得真实产物。
71. 作为项目用户，我希望部分步骤失败时看到分步结果，以便保留已保存成果并决定后续处理。
72. 作为项目用户，我希望刷新、断线或执行器重启后恢复进度，以便工作不中断或重复发布。
73. 作为项目用户，我希望取消后不再提交新动作或发布迟到结果，以便能可靠停止工作。
74. 作为项目用户，我希望重试复用已保存版本、任务和观察，以便不会重复制作或重复计费。
75. 作为项目用户，我希望不同用户、项目和需求之间保持隔离，以便内容与条件不会串用。
76. 作为项目用户，我希望素材中的指令只被当成内容，以便不会改变任务权限或授权。
77. 作为项目用户，我希望预算耗尽、无新信息或硬条件冲突时清楚收束，以便不会无限循环。
78. 作为项目用户，我希望公共回复使用直观术语而不泄露内部协议或凭据，以便理解实际结果。
79. 作为项目维护者，我希望模型、采样与窗口策略可在所属模块修改，以便不在前端和多个提示词重复维护规则。
80. 作为项目维护者，我希望用人工标注样本报告质量与开销，以便能解释设计收益而不依赖模型自评或虚构百分比。

## Implementation Decisions

### 范围、术语与架构

1. **I-01：增量改造。** 复用既有自然语言接纳、语音/视觉分析、混合检索、局部修改、方案历史、预览/导出、任务回执和恢复。现有可用能力不得因接口整理回退。历史 Issue 的状态不自动等同实现状态，实施先核对代码及验证记录。
2. **I-02：框架与模型。** 保留一个 LangGraph 主 Agent。文本推理使用 DeepSeek Flash，承担请求理解、工具决策、内容组织与公开答复；需要模型生成的导航概要也复用该文本推理能力。ASR、VLM 和文本 Embedding 使用阿里云百炼的对应模型。沿用 DeepSeek 对话适配，核对 Flash 的工具调用与结构化输出契约；提供方原生协议由各自适配集中处理。模型身份、参数和提供方配置可追溯，首版不训练或部署研究模型。
3. **I-03：部署与持久状态。** 保留既有 Spring 业务、Python 分析/Agent、Java 媒体 Worker 及本机基础设施。PostgreSQL 是业务状态权威来源，Qdrant 是可重建索引，LangGraph checkpoint 保存运行恢复状态，不替代制作会话或方案版本。
4. **I-04：术语与展示。** 内部使用制作需求、制作请求、制作需求简报、候选片段、编排剪辑方案、成片定义、方案版本和原始观察证据。对用户可展示剪辑要求、剪辑草稿、剪辑时间线和视频内容记录；“时间线”对应一个成片定义的有序片段，不合并或删除多输出模型。
5. **I-05：高内聚职责。** 对话/Agent 集中理解目标与选择动作；视频理解集中时间组织、检索、阅读、采样与覆盖；模型适配集中 DeepSeek 与百炼各自的请求、解析与用量；业务控制集中身份、范围、授权、预算、幂等和发布资格；方案/渲染集中范围、字幕、版本和产物执行。职责沿用既有部署，不新增自主 Agent 或通用工作流引擎。
6. **I-06：低耦合 Interface。** Agent 只消费规范化记录与业务结果，不接触数据库表、SQL、物理文件路径、Qdrant 配置或 FFmpeg 脚本。视频理解不依赖讲话/混剪模式；模型适配不重新解释聊天；方案模块不自行检索决定选段。可信权限上下文由业务注入，不接受模型自报身份。

### 用户目标与信息获取

7. **I-07：理解后接纳。** 原消息先持久接纳，单 Agent 理解目标、对象、条件及明确步骤，业务核对后保存固定制作请求及执行对象。纯查询不创建方案版本或占用编辑权；讨论不被接纳成执行。解析结果与原消息、需求和任务关联，重试不重新猜对象或改写原输入。
8. **I-08：要求与对象。** 明确条件、偏好和已说明默认值分别记录来源。新需求隔离，后续消息仅更新提到字段。默认时长沿用既有已说明 30–45 秒初稿；“必须”与“大约”分别处理，近似目标保存为偏好并报告实际偏差，兼容转换出的允许范围须明确说明来源，已有硬条件不静默放宽。素材名称和版本歧义按既有优先级澄清；发送时对象固定，历史修改基准不必是最新版本。
9. **I-09：三层表示。** 保留原始观察，建立引用观察的有界时间窗口检索单元，并提供按时间排列的完整内容目录。目录和素材摘要是导航，原始观察才支持具体结论。三层可以重建派生内容，不重付成功分析。
10. **I-10：时间与来源。** 完整音频 ASR 保留句/词时间及源音画偏移；视觉观察保留代表帧身份与实际 PTS。语音、画面、可见文字分别记录。帧时刻不自动变成持续区间，时间先后不自动成为因果，同名对象不自动成为同一实例。
11. **I-11：窗口与目录。** 首版用完整语句确定性分组和有界重叠，不逐窗口调用 LLM 改写或抽实体。目录先由时间范围与原文摘录组成；确需章节概述时从已有内容生成带引用的概要并缓存。全片回答使用完整目录或明确覆盖全片的导航提要，阅读不足时不得声称全片完整。窗口长度、重叠、返回量通过样本固定。
12. **I-12：检索与发布。** 复用中文稠密向量、BM25、原文短语与 RRF。各通道召回前限定授权项目、素材、来源和已发布有效分析/索引代次；召回后再核对来源。不同模型向量不得混用。新窗口规则重建派生索引；未发布、已取消或旧尝试结果不进入有效召回。
13. **I-13：视频理解 Interface。** 对主 Agent 提供素材列表、完整内容概览、内容检索、时间范围阅读与定向补查。目标工具为 list_assets、get_video_overview、search_evidence、read_video_range、inspect_video_range；复用现有检索并保留旧读取入口兼容。工具返回来源、实际时间、版本、覆盖、分页/截断、无法判断项、读取回执或依赖任务；内部决定模型和采样，不由 Agent 任意设置底层参数。
14. **I-14：定向观察。** 补查请求包含真实素材范围与检查目标，先复用已有单帧能力，再按状态变化类问题增加有序多图。百炼调用返回可见事实、支持输入及无法判断项，观察与推断区分保存。一次多图请求关联全部帧，时间由媒体记录回填；合法 JSON、模型置信分数和相关性判断都不能证明事实正确。
15. **I-15：观察生命周期。** 补查成功与“找到了所问内容”分别表达，不能只按描述是否字面包含查询判断调用成败。新观察追加保存，本轮可凭合法读取回执继续，不等待索引发布；后续增量进入有效检索并可按范围读取。无命中时先核查阶段、改写或浏览；纯视觉目标缺少候选时可在授权内扩大覆盖，否则说明无法确定。
16. **I-16：缓存与读取证明。** 缓存绑定素材哈希、分析版本、实际帧、采样、模型/参数和提示版本，定向结果另绑定检查目标；通用观察可复用，问题结论不可盲目复用。资料工具统一产生读取证明，绑定合法记录、有效范围、版本和需求/逻辑执行链。恢复任务只继承明确关联且仍有效的读取，不放宽成任意历史曾读取；方案校验统一认可批准资料工具，不写死某个旧工具名。

### Agent 循环、预算与等待

17. **I-17：目标状态。** 主循环维护目标、制作需求简报、已读引用、简短信息缺口/待办、方案草稿与固定基准、等待对象、实际产物。技术预算和权限属于可信执行上下文。通过明确业务状态逐步减少分散布尔开关，不要求保存或公开私有思维链。
18. **I-18：受限 ReAct。** 模型根据每次反馈选择下一步。简单问题直接定位/阅读，复杂任务按需维护轻量待办，不强制长计划或独立分类/审稿 Agent。草稿检查、保存和产物启动后返回主循环，判断后续明确步骤；模型提出结束须由实际结果核对，不能因任一工具调用成功立即结束。
19. **I-19：停止条件。** 分别处理目标完成、用户补答、依赖等待、授权等待、预算耗尽、无新信息、条件不可满足和取消。相同输入与版本已有结果时复用；反复无新观察/覆盖时不重复相同补查或无限改写。不可满足条件解释冲突，不猜答案或降低硬要求。
20. **I-20：补查治理。** 首次新增付费画面补查先展示项目、用途、限额及费用估算并取得可撤回项目授权；授权后每制作需求默认累计最多 4 次新增视觉调用，覆盖查询、选段、修改、补答、恢复及关联重试。扩大调用或完整分析需独立明确批准。额度、帧数、输入量、token、步骤与耗时分别受控，多图一请求不等于一张图费用。
21. **I-21：费用与不确定执行。** 调用提交前由业务预留/核对额度，记录提供方身份、请求、状态、用量和估算；Agent、目录摘要、Embedding 与视觉调用分别记录，内部多次请求不得隐藏成一次外层工具费用。预警不是授权或金额硬上限；回执不明确时保留身份与占用，先核对已有执行，不能自动重付。观察复用不再次扣新增模型额度，但仍检查权限。
22. **I-22：持久等待。** 用户补答绑定问题与原需求；分析/渲染等待绑定真实任务和固定对象；授权等待绑定具体未授权动作。暂停释放执行资源和按规则释放编辑占用，依赖完成事件恢复，无需用户再次发“继续”。恢复再次核对基准、预算、取消、租约和发布资格；不占用单执行槽轮询等待同槽分析。

### 选段、方案与实际产物

23. **I-23：统一成片定义。** 生成、组合、完整拼接、替换与精简都表达为既有成片定义中的有序源区间。初次生成提交完整片段列表，程序分配业务身份并派生原文字幕与渲染配置。局部修改继续引用未改 clipId，由程序复制目标外内容并追加完整版本，不要求模型重写全部输出。
24. **I-24：约束分类。** 项目归属、素材有效性、时间范围、版本/编辑权、字幕映射及有限容量是程序正确性约束；必须参与素材、顺序、交错、回放、重复策略、时长硬要求与偏好是任务条件。旧短视频限制保留兼容，通用编排阶段将固定模式限制迁为受控能力/任务策略，不能只删除上限而忽略字幕、输入和渲染容量。
25. **I-25：亮点选择。** 浏览完整结构，寻找并比较多个候选，阅读铺垫与结论，按主题相关、观点完整、信息量、重复与时长适配选择。默认标准明确说明；关键审美差异无法推断时才追问。视觉条件独立核查，摘要和第一个命中不能单独支持“全片最精彩”。
26. **I-26：组合与完整拼接。** 语义整理检查重复、缺口及连接上下文；用户明确完整拼接则按合法完整素材范围执行，不擅自删改。内容判断需要原始观察，机械组合需要已接纳用户要求和合法素材范围。新增受控操作依据适配现有证据契约，不能让模型传空引用绕过校验；字幕按用户要求保留来源，无音轨不伪造语音。
27. **I-27：通用编排扩展。** 按用户明确条件支持素材交错和回放，默认不靠重复区间凑时长。长时间线仍有可配置容量；验收覆盖超过现有 10 段的有界编排及长字幕。实际最大段数、时长与请求量依据本机媒体测试固定，并返回具体能力限制。第一阶段不自动取消现有规则，扩展阶段需同步修改校验、字幕和渲染并验收。
28. **I-28：检查与保存 Interface。** 读取固定方案、检查草稿、保存版本、请求预览、查询任务、确认版本与请求导出围绕业务动作提供小接口。草稿检查返回结构化问题、定位字段和实际时长；保存重新校验当前要求、基准与编辑权，并幂等追加版本。检查通过不构成永久保存许可。模型只提出内容，必经检查与保存可由图节点组织。
29. **I-29：历史与修改。** 保留不可变方案版本及修改来源，允许从旧版继续追加，当前查看不改变执行基准。目标外片段、其他输出及未修改要求由程序保留；修改重映射完整字幕与时长。基准竞争报告冲突，不自动换成最新版本；草稿迭代和无实际变更不重复创建业务版本。
30. **I-30：完成核对。** 内容答复需合法已读来源；推荐片段需可定位范围；方案需保存回执；预览/导出需固定版本任务成功且有效产物。程序核对引用、要求、对象、状态和可用性，语义质量另行评测。启动任务仅报告进行中，保存方案不等于完成“剪成视频”；阶段失败保留已完成成果并说明剩余步骤。
31. **I-31：授权不变。** 制作不自动预览；明确请求的查找→制作→预览可连续执行并绑定实际新版本。正式导出仍需具体版本确认及另行明确导出指令，新版本不继承确认。未来版本、含糊评价、素材指令和模型待办不构成授权。默认自动预览/导出不纳入本规格。
32. **I-32：执行一致性。** 保留同会话串行、方案编辑互斥、事务 Outbox、公开事件恢复、租约/尝试校验、幂等回报、取消竞争和迟到结果拒绝。副作用关联已接纳请求；恢复优先读既有结果，不重新分配身份。同一逻辑执行的模型/工具/修正额度不随恢复或连续子步骤重置；真正新增用户轮次按轮次策略管理，需求级新增视觉累计额度仍不重置。
33. **I-33：逻辑数据关系。** 新增或扩展记录须明确需求及条件来源、目录/窗口原始引用、读取证明、补查输入/观察/用量、授权及累计额度、依赖任务与恢复对象。以既有持久记录为基础，不冻结额外通用记忆表或任务系统。原始观察不可变，派生索引可重建，历史引用受保护；数据迁移与版本兼容必须验证。
34. **I-34：公开反馈。** 展示目标、所读内容、选择依据、进度、实际版本与产物及具体限制，不展示私有推理、执行协议、凭据或内部路径。仅展示决策所需预算摘要，不把提供方细节加入用户制作流程。公开任务事实由业务发布。

## Testing Decisions

### 测试接缝与原则

1. **T-01：主要接缝沿用既有公开业务 HTTP。** 从制作会话提交原文、读取公开事件与结果，检查素材记录、方案版本、任务及产物。已有需求与实施记录已确认该接缝及真实集成，沿用既有确认，不为内部模块新增独立验收入口。
2. **T-02：浏览器检验关键用户闭环。** 覆盖同一聊天入口查找→制作→指定片段修改→明确预览→具体版本确认→明确导出，以及刷新、补答、取消和结果播放。浏览器作为既有用户表面补充，不重复为每个内部工具建立另一套验收。
3. **T-03：好测试检验外部行为与不变量。** 检查实际对象、合法来源、目标外稳定性、权限、用量、任务终态和可播放文件；不绑定私有方法、图节点名、完整提示词、隐藏推理或某次模型措辞。数值时间等确定性规则可补充小范围规则测试，不能用其替代完整流程。
4. **T-04：必要真实集成。** 保留真实 PostgreSQL 事务/竞争、对象存储与播放、Qdrant 分词/发布/过滤、消息重复派发与恢复、百炼协议/回执和 FFmpeg 输出验证。模拟提供方只用于可控故障与协议场景，不证明模型识别或回答质量；预置观察只用于业务规则测试。
5. **T-05：测试模块与先例。** 视频理解复用既有 SearchIndexApiIntegrationTest、VisualApiIntegrationTest 及语义检索/视觉浏览器场景；Agent/恢复复用 ConversationApiIntegrationTest、ConversationRecoveryApiIntegrationTest 与自然语言/取消/回执场景；方案复用 EditPlanApiIntegrationTest 与局部修改/混剪场景；产物复用 PreviewApiIntegrationTest、ExportApiIntegrationTest、RenderCapacityIntegrationTest 与历史导出场景。测试仍通过公共 Interface，不新增仅供测试的内部能力入口。
6. **T-06：真实模型与确定性不变量分开。** 权限、预算、幂等、版本及授权必须在回归样本中全部通过；模型内容质量用人工核对原素材，不采用模型生成标准答案或自评置信度。短暂视觉遗漏可报告覆盖不足，不能算作可靠否定。

| AC-29 | 取消与完成竞争、过期尝试迟到、基准竞争 | 只有有效执行发布；占用正确释放，取消后无新动作或迟到成果 |

| AC-31 | 无新信息、不可满足硬条件、模型/工具/补查预算耗尽 | 有限停止，说明缺口与已完成部分，不循环猜测或创造新任务重置预算 |
| AC-32 | 完成问答、片段推荐、方案、预览及导出各类目标 | 完成声明分别对应来源、范围、保存版本或真实可用产物 |

### 内容质量与开销评测

7. **T-07：诊断样本。** 首轮使用 3–5 个代表中文视频、30–50 个固定人工标注问题及若干选段/编排样本，标注正确来源、时间、独立观点和视觉条件。覆盖局部精确信息、上下文、全片步骤、时序、视觉细节、语音提及/画面出现区分、短暂文字和无法确定身份。样本量是诊断起点，不作为泛化或稳定尾延迟保证。
8. **T-08：分项对照。** 保留当前完整实现作为真实基线；分别增加窗口/范围阅读、全片目录、根据反馈的工具选择与定向观察，固定模型版本及共同基础观察。额外观察单独计费并在各对照隔离，避免补查结果污染基线。可用固定工具脚本诊断检索因素，但最终仍测试完整 Agent 行为。
9. **T-09：指标与失败分类。** 报告正确来源的 Recall@K、主张支持率、全片遗漏、边界误差与观点完整性、错误否定、恰当无法回答、无新信息重复动作、实际新增 VLM 次数/帧数/token、缓存命中及冷/热费用和延迟。归因到采样、观察、表示、召回、阅读、动作选择、停止或执行；不只报告调用次数下降。
10. **T-10：通过与限制。** 回归不变量全部通过；新增能力对应标注样本中的实际缺口得到核查，质量/开销变化有逐项记录。通用编排扩展必须实测长字幕、资源峰值和实际播放。没有既定改善百分比或秒级 SLA；参数与容量依据样本固定并记载版本，未验证条件如实报告。若无可重复收益，不默认增加图谱、视觉向量或更多 Agent。

## Out of Scope
