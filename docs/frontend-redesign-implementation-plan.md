## 阶段划分与执行规则

本次前端重构为一个完整阶段，下列六步是内部交付步骤。每步先验证当前行为，再运行所在模块与直接受影响模块回归；步骤 6 完成必要审查修正后，统一执行一次 Java、Python 完整非付费回归、后端打包及前端类型检查、构建和有效浏览器链路验收。

不因完成单个函数、组件或步骤重复执行服务全量。只有改动共享基础代码或无法明确影响范围时才扩大。全量后的局部修正补跑相关回归，记录最终代码实际通过的检查；必要时重新执行对应服务全量。

各步按顺序推进；未通过本步验收与必要回归，不将本步标为完成。先前已按授权完成步骤 3、4、5；本轮用户明确授权完成步骤 6 并更新本机部署。

## 验证环境与测试选择

### 测试分层

| 层级 | 用途 | 约束 |
| --- | --- | --- |
| 静态检查与实屏审查 | 类型、构建、排版、导航和可访问性 | 不为纯样式或一次性文案新增镜像实现的测试 |
| 浏览器 HTTP 边界测试 | 输入、对象绑定、请求次数、禁用、恢复与异常 | 使用受控数据，覆盖业务行为，不把 mock 当真实服务验证 |
| 隔离真实服务与媒体 | Java、数据库、MQ、存储、FFmpeg、播放和下载 | 使用现有 LocalMedia 隔离环境和受控 Agent 结果，不调用真实模型 |
| 真实模型与人工音画 | 模型理解与真实素材最终质量 | 单独安排和报告，优先复用已分析素材，不与日常自动回归混算 |

`frontend/e2e/conversation-lifecycle.spec.ts` 是现有新版 HTTP 边界入口；`conversation-lifecycle-live.spec.ts` 由 Java 的 `LocalMediaIntegrationTest` 注入隔离环境启动，是非付费真实媒体入口；`conversation-lifecycle-model.spec.ts` 为显式付费入口。后两者直接执行时可能因缺少环境而跳过，跳过不算通过。

历史浏览器测试不能按文件名直接归入默认回归。例如 `usage.spec.ts`、预览与导出测试可能依赖 `renderSeed`，该夹具在无缓存时会上传讲话素材并等待真实 ASR；部分测试还会重建 Compose 服务或依赖退役链路。步骤 1 必须逐项识别费用、环境和协议依赖。保留仍有效的业务断言，以现行公共入口和隔离夹具适配；不全量运行整个历史 Playwright 目录，也不为维持旧选择器而保留错误界面。

### 最小回归命令

以下为后续实施参考；步骤 1 的实际执行及结果见验证记录。前端命令在 `frontend/` 执行；指定真实存在、已核对依赖的测试文件及必要用例，不能执行尚未新增的计划用例。

```sh
# 前端当前行为的单条浏览器用例
E2E_BASE_URL=http://127.0.0.1:5173 npm run test:e2e -- conversation-lifecycle.spec.ts -g '<当前行为的用例名称>'
# 所在模块的浏览器边界回归及类型检查
E2E_BASE_URL=http://127.0.0.1:5173 npm run test:e2e -- conversation-lifecycle.spec.ts
npm exec -- vue-tsc --noEmit
# 模块完成后构建
npm run build
```

浏览器边界测试前先在独立终端启动 `npm run dev -- --host 127.0.0.1`。真实媒体验收前确保前端已构建；以下命令在仓库根目录串行执行 Maven：

```sh
RUN_LIVE_JAVA_ANALYSIS=0 mvn -B -ntp -pl backend '-Dtest=LocalMediaIntegrationTest#unacceptedAndSavedSilentDraftsRenderThroughMqWithTheirOwnSources' -Dlifecycle.browser=true -Dlifecycle.model=false test
```

浏览器测试新增或适配优先放在 `frontend/e2e/` 的对应业务文件。仅在现有文件受退役入口或付费夹具耦合、无法清楚隔离时新增必要的当前入口测试；不搭建通用测试平台。

## 步骤 1 建立实屏和契约基线

完成记录：[实屏、契约、测试清单与验证结果](verification/frontend-redesign-step1.md)。真实服务使用部署允许的 `http://localhost:8080`，Vite 入口仅用于受控 HTTP 场景；详见记录中的环境限制。

### 改动范围

- 核对登录、项目列表、三个工作区区域，以及当前有效对话生命周期的浏览器实屏。
- 核对上传到素材的关联身份、素材名称和时长、会话快照、预览请求与消息引用、方案版本、导出历史、用量和错误字段。
- 建立后续验收所需的页面状态与测试清单，记录无模型费用的夹具来源、执行入口和环境要求。
- 文档范围：本设计、计划和后续 `docs/verification/frontend-redesign-step1.md`。有必要时准备最小确定性浏览器夹具，不修改业务逻辑。

### 验收标准

- R1-01：1366×768、768×1024、390×844 三种视口的现状截图具备名称和场景，真实登录工作区与未覆盖状态明确区分。
- R1-02：每项拟展示字段可追溯到当前接口；上传与素材去重、草稿名称、预览来源等缺口有明确记录和最小处理决定。无数据的项目封面、更新时间、缩略图不纳入必做。
- R1-03：测试清单逐项注明新版／历史、mock／真实服务、是否付费、是否重建服务及是否作为本阶段门槛。
- R1-04：当前草稿、历史预览、多输出、只读、UNKNOWN、部分分析失败等状态均有验收数据准备方式；不靠运行真实模型生成所有状态。

### 回归范围与依据

文档和观察不运行应用测试。若新增或适配夹具，先运行对应单条场景，再跑所在测试文件；核对未把模型付费或共享服务重建引入默认命令。只检查该步差异与文档链接，不要求全量。

## 步骤 2 调整基础视觉与项目导航

完成记录：[实现、三视口实屏、回归与审查](verification/frontend-redesign-step2.md)。

### 改动范围

- `App.vue`：登录、账户、基础排版、按钮和表单层级；必要时将基础样式迁入一个 CSS 文件并由 `main.ts` 引入。
- `ProjectWorkspace.vue`：合并顶部信息，建立“素材／制作／作品”导航、主视图切换、有效视图偏好恢复与窄屏模式。
- 现有业务面板作为视图内容保留；用量移入次级面板，原有功能入口在后续步骤完成前持续可达。
- 适配 `projects.spec.ts` 中仍有效的项目隔离与窄屏导航断言，按步骤 1 清单准备非付费登录及导航场景。

### 验收标准

- R2-01：登录、注册、退出、创建及打开项目、返回列表和无权限反馈均保留；项目名和账户无需占用多层页头。
- R2-02：三个主视图在所有目标视口可达，当前项明确；不存在隐藏面板内仍可 Tab 到达的控件。
- R2-03：无素材的新项目进入素材引导；已有项目恢复有效视图。恢复失败使用当前可用默认视图，不恢复无权访问项目。
- R2-04：同项目切换不销毁上传、聊天输入或引用；切换项目和退出后不串用旧对象、播放链接和请求结果。浏览器返回／前进继续正确处理项目 URL。
- R2-05：全局按钮规则调整后，所有现有业务面板可读可操作；桌面、平板、手机截图无主内容横向溢出。

### 回归范围与依据

先跑登录／导航单场景，再跑当前入口的认证、项目、导航测试及类型检查、构建。基础 CSS 影响全部面板，补素材、对话、草稿、作品、用量的实屏冒烟；生命周期 HTTP 边界测试补跑，验证导航未导致组件重建或状态丢失。

`auth.spec.ts` 含数据库／API 容器重建，不能直接作为每次样式修改的默认命令；认证接口和会话逻辑未改时只验登录／退出／过期呈现。若实际改动认证、`api.ts` 或公共项目事件，扩大到直接依赖模块；影响无法明确时执行对应服务全量。

## 步骤 3 重构素材与内容查询

完成记录：[素材、查找、原片回看及验证](verification/frontend-redesign-step3.md)。

### 改动范围

- `UploadPanel.vue`、`AssetLibrary.vue`：统一条目展示，按真实关联去重，重排上传操作和可用状态。
- `AnalysisStatus.vue`：简化默认状态，保留阶段详情及允许的失败重试；索引维护控件从普通素材详情移入高级维护入口。
- `SpeechSearch.vue`、`InspectionPanel.vue`：查询与筛选层级、命中内容、覆盖说明、现有补查授权。
- `MediaPlayer.vue`：播放器优先、详情后置，保留定位、片段结束边界及签名续期。
- `uploads.ts`、哈希 worker、请求与恢复逻辑默认不修改；若展示必须取得已有关联，使用最小接口传递。

### 验收标准

- R3-01：同一个上传及其素材不重复展示；同名文件仍可分别存在，媒体验证中和已可播放明确区分。
- R3-02：暂停、继续、重选原文件、取消、过期、校验失败及延迟清理均有准确反馈；传输进度来自真实字节数。
- R3-03：语音成功／画面失败仍能使用已有语音；无音轨不报系统故障；可恢复失败只重试允许的阶段，成功阶段不重复提交。
- R3-04：查询参数和语义保持不变，筛选可发现；命中可回看准确原片及上下文；无命中、部分覆盖和稀疏帧限制不被隐藏。
- R3-05：候选复查及扩大补查的现有预算与授权仍生效；不因展开详情或切换素材自动发起新分析。
- R3-06：播放、时间定位、片段停止、播放签名续期和回到列表有效；普通播放不展示索引参数或内部 ID。

### 回归范围与依据

按上传、分析呈现、查询、播放分别先跑当前单行为，再跑模块及相邻场景。浏览器覆盖断点续传、同名不同内容、取消与空间状态、部分分析失败、原文／语义筛选、原片定位和补查授权；类型检查与构建通过后做三视口实屏检查。

`uploads.spec.ts`、`upload-resume.spec.ts`、`upload-cancel.spec.ts`、分析和搜索相关文件仅选择步骤 1 核对过的当前非付费用例；涉及真实 ASR、Compose 参数变更的项改用隔离或受控场景，另列有条件验收。若动到上传核心，扩大到全部受影响上传行为，并针对实际改动补 `UploadApiIntegrationTest`、配额／过期／空间相关模块。纯展示调整不重复运行所有 Java 分析和检索测试。

## 步骤 4 重构对话与草稿制作

完成记录：[双栏制作、来源回看、真实媒体及审查](verification/frontend-redesign-step4.md)。

### 改动范围

- `ConversationPanel.vue`、`DraftCard.vue`：工具栏、条件摘要、引用标签、澄清、输入区、草稿详情和确认反馈。
- `ProjectWorkspace.vue`：制作双栏及选中对象定位，窄屏对话／预览切换。
- `ArtifactPlayer.vue` 及预览消息呈现：同请求合并、原来源播放、失效与恢复反馈。
- 保留原文与引用请求、草稿绑定、幂等键、当前资格、SSE／快照关系；必要拆分限于当前展示职责，不复制控制逻辑。
- 适配 `conversation-lifecycle.spec.ts` 和隔离真实媒体浏览器用例，保留业务断言，更新已变化的文案和定位方式。

### 验收标准

- R4-01：普通讨论、证据问答、制作、指定输出修改、待澄清补答和中途独立问答均保持既有语义；引用使用名称且可移除。
- R4-02：桌面对话与预览可并看；窄屏切换不丢输入、引用和选中对象。中文组词不误发送，回看历史不被新消息强行拉走。
- R4-03：草稿显示标题、时长、画幅、字幕及可回看片段；聊天历史可定位详情，只有一组当前草稿操作与幂等状态。
- R4-04：单输出直接预览，多输出先选一条；确认前可预览，未预览也可确认，确认覆盖全部输出且不自动导出。
- R4-05：开始修改使旧稿只读；失败或停止不会恢复过期资格；已确认后可以继续问答或新制作，不能派生编辑已冻结版本。
- R4-06：同请求无重复状态卡；不同请求及历史预览仍保留原来源。过期签名续签同产物，不触发重新渲染；文件失效仅在允许时开放显式重试。
- R4-07：停止回复、预览互不连带；刷新恢复窗口外当前草稿及媒体任务。重复点击／响应丢失沿用原请求身份，不新增用户消息或错误绑定其他草稿。
- R4-08：UNKNOWN 和预算耗尽保留原因且无强制重试；当前制作已变更后历史失败不能回写。

### 回归范围与依据

先跑当前行为，再跑整个 `conversation-lifecycle.spec.ts`、新增必要导航／输入交互用例和类型检查。构建后运行非付费 `LocalMediaIntegrationTest` 对应浏览器场景，验证真实草稿预览、冻结版本、导出与播放的衔接。

草稿展示与作品导出共享来源身份，补作品选中版本、确认状态及从聊天前往作品的回归。若修改公共事件或请求协议，补 `ConversationRecoveryApiIntegrationTest`、`AgentRunsApiIntegrationTest` 等直接模块；跨语言契约或哈希改动则扩大到 Java/Python 双方契约和工具调用。此类业务协议改动不是本步预定范围，必须记录原因和实际扩大范围。

## 步骤 5 重构作品与用量诊断

完成记录：[作品导出、用量诊断、真实媒体及审查](verification/frontend-redesign-step5.md)。

### 改动范围

- `PlanPanel.vue`：作品列表、版本／输出选择、播放器、导出清晰度、导出历史、文件状态与危险操作。
- `UsagePanel.vue`、`AnalysisStatus.vue` 及项目次级面板：用量摘要、预警、明细、诊断和索引维护的组织。
- 只根据现有字段显示名称、费用和错误；发现缺失字段时记录最小契约缺口，不增加计费或权限模型。

### 验收标准

- R5-01：已确认方案无成片时显示“待导出”；单版本直接查看，多版本可选择，多输出每次导出一条，规格在提交前明确可见。
- R5-02：已由草稿整体确认的版本不重复要求确认；历史未确认版本仍须明确确认，未确认不能导出。
- R5-03：导出请求固定版本和输出；切换作品／版本不会重定向正在运行任务。停止导出不停止聊天或预览，不删除成功产物。
- R5-04：真实 720p／1080p 成片可解码、播放时间推进并可下载；失效文件、删除中、已删除有准确状态。删除前明确确认，原素材保留。
- R5-05：导出历史可查看，刷新恢复实际任务和文件状态；重放操作不重复提交相同请求。
- R5-06：用量显示估算与未知费用、已用／预留／待清理区别；预警可保存并刷新恢复，文案明确不阻止执行。
- R5-07：普通流程无制作／校验 ID、编辑代次或索引参数；现有维护能力可从次级入口到达，打开面板不自动执行分析、重建或付费操作。
- R5-08：错误提示保留真实原因和有效下一步；技术详情不泄漏凭据、私有路径或内部推理，未知错误不被统一掩盖。
