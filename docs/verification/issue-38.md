# #38 聊天预览、确认与导出

沿用已确认的公开 HTTP、真实 PostgreSQL／对象存储、真实模型与浏览器测试边界。以 #36／#37 为前置，复用现有预览、确认、导出及渲染能力。

## TDD 与行为

- 预览意图最初被拒绝。消息发送时保存查看版、会话生成版本和明确引用；理解接纳时固定目标。优先明确引用，其次发送时查看版，再其次本会话最近生成版；明确版本号跨方案不唯一、多个引用或相互冲突时在原聊天框提问。
- 确认／导出意图最初被拒绝。现在分别接纳，确认仅绑定不可变版本；另发明确指令后才导出真实成片，并固定配置。新版不继承旧版确认，未确认时说明原因。
- 业务独立检查用户原话与明确选择。普通评价、查询或引用指令、未来条件及同一消息合并确认与导出不产生授权。模型不能用猜测的版本号覆盖发送时的对象。
- 对象补答最初错误要求重复整个操作句；现在沿用原问题的明确操作，只补充选择。“随便”不能被模型当作明确选择；不存在的版本保留同一个原问题，避免多份等待。原需求、解释及执行记录持久关联，重试保留固定对象和需求身份。
- 真实浏览器发现预览下载被限制为正式成片；将通用下载能力集中到媒体产物模块，保持权限、可用性检查，预览与正式成片均可下载。
- 导出已经接纳但聊天答复丢失时，最初重试仍读取已缺失原素材。现在在存储检查前识别该消息的已接纳记录，恢复原回执，不创建第二份导出。

- 审查发现版本目录无数量上限。新增公开接口测试先失败，再限制模型候选为 12 个；旧版本按发送时的历史范围精确查询，发送后新建版本不能改变旧指令目标。复审进一步用真实未提交事务复现时间戳边界失效：改为固定发送时查看方案的最大已提交版本号和聊天消息序号，保持旧版本可查且排除之后才提交的版本。

## 单票验证

公开 HTTP 文件：ConversationApiIntegrationTest、PreviewApiIntegrationTest、ExportApiIntegrationTest。覆盖发送后换版、明确引用优先、禁止模型猜版本、独立确认／导出、未确认新版、项目权限、同输入框对象补答、重复工具回执、丢失答复恢复以及实际对象存储下载。

真实浏览器闭环 1/1 通过：无查看版时预览最近生成版；实际低清 MP4 播放下载；确认 V1；生成并查看真实 V2；普通评价与未来导出不确认 V2；V2 未确认拒绝导出；当前查看版预览使用 V2，明确导出 V1 使用已确认的 V1；重复发送只保留一份导出；刷新后播放下载正式 MP4；查询引文不制造授权；同时引用两个版本先问，再在原输入框回答“第一版”继续。

前端类型检查／生产构建和 Python 语法检查通过。日志位于 backend/business-api/target/issue-38-*.log；最终统一回归与双轴审查完成后补充结果。
