# Issue #10：查找人名、数字和原句并跳转核查

2026-10-10，以真实百炼转写的固定讲话视频验证原文字面查询。与 #9 同样使用北京原生异步 ASR；本票不将原文字面查询称作语义检索。

## 查询、证据与上下文

`POST /api/v1/projects/{projectId}/search` 先验证项目归属，再通过当前分析头、源 SHA-256 和有效素材范围查询语音检索单元。原查询作为参数传入 PostgreSQL `position`，不使用拼接 SQL 或通配符模式。查询长度最多 256 个字符、结果最多 50 条；界面默认取 20 条。

返回素材身份、源校验值、分析版本、原文、语音来源、原素材时间、检索单元与原始证据引用。候选窗口标为 RETRIEVAL，界面明确要求回看原视频后决定最终剪辑切点。播放授权另行验证，首次加载元数据后应用命中位置。

`GET /api/v1/evidence/{evidenceId}/context` 在读取目标时限定登录用户、当前分析版本及源校验值，再返回同一素材的邻近原始语句。默认每侧 5 秒，最多每侧 30 秒、5 条邻句；保留原始语句及观察时间，不将间隔表述为连续命中。

响应覆盖信息包括有效素材、语音状态、素材时长及已成功处理的音轨范围。固定样本经独立 ffprobe 核查：素材 14.044 秒，音轨从 1.436 秒开始、长度 12.608 秒；已分析语音范围为 1.436–14.044 秒。媒体元数据没有可确认音轨时长时不虚构处理范围。未完成或不适用的语音没有已处理范围。

## 真实边界验证

- 查询接口先因不存在返回 404，再通过真实转写返回与原始证据一致的 ID、版本及源哈希。
- 浏览器查找入口及上下文按钮分别先失败；实现后查询卡片可展开邻句并定位原视频。
- 人名“张明”、数字“三个”、原句“核查原文”和中文逗号正确匹配原文。`%`、`_`、反斜线、SQL 注入字符串及不存在的短语均没有被当作通配或 SQL 执行。
- 结果数量、查询长度和上下文范围超限均返回 400。
- 未命中显示已查素材、语音来源及处理范围，并解释识别可能遗漏；没有完成语音分析的空项目准确说明尚无语音证据。
- 两个账号各自上传包含同一句话的视频，各自查询只有本项目素材；跨项目搜索及读取对方证据上下文均为 404。同账号新增空项目不会混入另一项目的命中。
