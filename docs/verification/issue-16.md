## TDD 与协议

- 项目一致快照 404 → REPEATABLE READ 下恢复消息、当前任务、查看版本及执行尝试草稿；按项目所有者鉴权。
- 项目 SSE 404 → 持久公开日志与项目行锁游标，同一游标重复订阅重放相同事件；消息与任务变更在提交时转换成白名单字段。
- 草稿回报 401（尚无入口）→ 当前任务／尝试／租约受控入口；producerSeq 幂等，版本与 Unicode 码点位置校验，未知事件与多余私有字段拒绝。
- 正式答复后仍恢复未完成草稿 → 同事务标记当前尝试草稿完成；最终业务消息始终是正式答复的权威。
- 日志回收未执行，旧游标仍 200 → 可配置日志保留期、原子推进保留边界，410／stream.reset 触发重新获取快照；正式消息不清理。
- 两个真实 PostgreSQL 事务交错提交：先事务已分配游标但未提交时快照没有该消息；后事务等待项目计数器，先后提交后 SSE 按顺序重放，两条消息均恢复。

公开活动为固定阶段枚举；模型 reasoning_content、普通 assistant content 和原始工具参数不转发。DeepSeek 使用真实流式工具协议，仅解码 answer_query 的顶层公开 content，合批写入业务草稿。临时草稿明确标记未完成，候选和草稿不能替代正式发布。
