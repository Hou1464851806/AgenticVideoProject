## 实现

- `tools/QuestionScopes` 在 PostgreSQL repeatable-read 短事务内保存可信项目/素材范围、原素材哈希、分析版本、就绪来源、语音处理范围、实际视觉采样和索引代次，并冻结可见原始证据及检索单元身份。后来发布的来源和切换的 heads 不进入旧快照，新普通消息可创建新快照。
- `QuestionToolController` 复用本机内部 Bearer 认证，提供快照创建/恢复和四工具入口。模型只传工具参数，不能指定项目、范围或凭据。未探测素材保留未就绪元数据；必要依赖失效显式停止。
- `ReadTools` 负责严格参数、Python 兼容请求哈希、范围核验、调用身份、回执及32768 UTF-8字节分页。四个真实工具返回 `mock=false`，不接纳后台分析或自动等待任务；同身份内容冲突、未完成调用和来源未就绪分别返回明确类别。
- `search/QuestionEvidence` 拥有固定可见范围的原始读取和混合检索业务，使用独立的可信输入记录，不反向依赖工具模块。语音按时间交叠读取并保留原始句段、音轨时间和字词观察；视觉点按 `[start_ms,end_ms)` 选取，返回 `observed_at_ms/time_kind=POINT`，不制造1ms区间。
- 目录从保存的事实生成导航条目，`records` 为空；目录页尾与实际分析覆盖分别报告。素材、目录及原始证据采用稳定排序，分页累积不覆盖前页，单条超限明确报错，原文不截断。
- 稠密、BM25 和原文通道独立反馈状态。Qdrant 召回前按冻结索引代次和各素材已经就绪的来源过滤，再回查 PostgreSQL 快照证据；稠密失败不阻断 BM25/原文。每通道至多50候选，融合至多100单元，候选截断和来源覆盖分别返回。
- 检索条件规范化默认值、素材/来源排序并排除 cursor；排名只构建一次并持久保存，后续翻页及同条件新调用复用。查询模型回执关联排名身份，保存完整响应、向量、提供方请求身份和用量；提交不确定停止该查询的自动重付，同模型/维度的其他分组也不重复提交。
- 新增 V51；范围、工具回执和排名不绑定旧 Agent task/attempt/lease。收敛了工作区未接通的 `qa/` 骨架，避免保留重复 Spring 服务或另一套快照查询层。没有新增动态工具框架、插件网关、Python 服务或旧每任务工具次数限制。

操作和完整 HTTP/分页/错误说明见[后端 README](../../backend/README.md)。
