# #17 停止对话任务并关联原需求重试失败

基线 `8a91721`；前置 #15 已完成。沿用公开 HTTP／真实 PostgreSQL，以及 Compose、真实 DeepSeek 和故障注入 HTTP 提供方的验证边界。

## TDD

- 失败关联重试入口 404 → 新任务／轮次关联原失败任务，保留原用户消息与固定输入；幂等返回同一任务，旧失败与旧尝试不得发布；已成功结果直接返回。
- 模型回执未知时重试仍 202（期望409）→ 显式 `acknowledgeUnknownCost`，接受未知费用后才创建新调用；确认选择持久保存在重试接纳记录。
- 模型响应头等待时没有停止按钮 → 加入显式停止。之后任务超过15秒仍停在 CANCEL_REQUESTED → 使用 HTTPX 可取消本地 HTTP 等待，关闭连接，执行退出后回报取消并释放会话。
- 远程查询 Embedding 阻塞时，停止后仍不能释放执行器 → 工具 HTTP 等待共享同一可取消传输；业务端继续核对当前任务／尝试，远端迟到结果无法发布。
- 阻塞 Embedding 的费用提示误为已知 → 查询调用持久关联 task_id；同步模型与查询 Embedding 尚无回执时都明确费用未知。远端计算与收费不能保证撤销。

## 已验证闭环

- 公开 HTTP 失败重试、重复与竞争请求、跨账号拒绝、成功提交后回放、旧任务迟到结果拒绝。
- 五轮停止／完成竞争：只有成功发布或撤销发布资格两种结果；成功结果不会被迟到取消改写，取消必须确认执行退出，结束后可接纳下一轮。
- 原方案失败后重试取得同一方案编辑占用，排队任务停止后释放占用；原固定素材失效时拒绝重试且不生成任务或消息。
- 真实 DeepSeek 重试：先用HTTP提供方503造成未知回执，界面要求费用确认；恢复真实提供方后提交同一原需求，历史一条用户消息、一条助手答复，刷新保留。
- 模型响应头阻塞时停止，在15秒测试窗口内结束并释放会话；随后真实模型执行新需求，迟到原答复不能发布。

首次重试浏览器问题包含“确认”而被现有制作命令路由作为澄清请求接纳，没有触发模型失败；测试已改为明确的素材核查问题并断言任务类型。HTTP测试集合增加账号后触发默认20次／分钟认证限额，测试环境额度设为100，生产限制不变。
