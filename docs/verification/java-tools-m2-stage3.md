# M2 阶段 3：显式保存与版本消费兼容

日期：2026-10-15（Asia/Shanghai）。实施基准 `09d7bfb`，起始分支 `main`、工作区干净。依据阶段 2 交接与 [M2 最终设计](../java-tools-m2-design.md)，本轮仅实施阶段 3。

## 实现及边界

- 新增内部认证的显式保存与结果查询，沿用阶段 1 SaveRequest／SavedResult。保存请求补齐客户端 `requirements_sources` 字段，跨语言契约及共享样例同步；V53 增加版本上的条件来源 JSON，不更改草稿和条件的哈希。
- `ProductionSaves` 管理资格核对、短事务及保存重放；`ProductionDrafts` 继续管理绑定／校验发布；它们以制作需求行锁串行化提交。工具入口只做传输，模型没有保存工具。
- 仅使用持久通过回执的规范化内容；匹配项目、制作需求、scope、校验身份和两种哈希，拒绝不通过及已有不同草稿／条件校验的旧结果。保存时锁定并核对固定数据库依赖，不改用新 head、不重新分析。
- 全部输出作为一份新方案 V1 原子保存，分配 outputId／clipId、保存映射及素材／证据引用。业务版本自身同时记录来源及保存结果，不伪造旧 AGENT_TURN，不产生确认／渲染任务。
- 重复／并发请求及响应丢失后的查询返回同一版本；数据库异常上抛、整体回滚，原请求可重试。已经提交的结果可在依赖后来失效时查询和重放。新校验被拒绝，已保存制作只读。
- 既有账号鉴权版本读取增加 M2 `productionSource`；保留完整草稿、条件、条件来源、scope／校验／调用、哈希、规则、证据／读取引用及输出映射。客户端原文来源是可追溯元数据，不等于 Java 已证明自然语言理解正确。
