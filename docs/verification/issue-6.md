# Issue #6：断网、暂停与刷新后继续原上传

2026-10-10，继续使用真实 PostgreSQL、Silo 与 Compose 浏览器边界。

## 先失败后通过的验证

- 暂停时让已发出的分片 PUT 收敛并登记；继续只上传缺失分片。实际断网后第二片有限重试，PUT 序列为 `[1,2,2,3]`，第一片没有重复传输。
- 授权请求在途时点击暂停，最初仍发出 PUT；补上授权返回后的暂停检查后，暂停期间 PUT 数为零，继续后为一。
- 两个文件占满共享执行槽，第三个排队文件暂停后立即继续，最初被忽略；修复队列状态切换后三个文件均完成。
- 第二片持续网络失败，恰好三次尝试后显示可继续的原因，第一片保留。恢复网络并手动继续只补第二片。
- 刷新重新选择同名同大小但内容不同的文件，被 SHA-256 校验拒绝且没有新增 PUT；正确原文件继续只补缺失分片。增量校验使用独立 Worker、2 MiB 读取块并显示进度，不持久保存 File。
- 用真实新标签页竞争同一会话，明确返回另一页面持有资格的错误，没有发出 PUT。创建／恢复要求页面实例 writerId，普通查询不披露 writerToken。
- 把实际 Silo 签名期限设置为三秒并等待四秒，首个 PUT 得到真实 403；客户端重新签发原会话地址后返回 200。只有一次创建、一个 S3 上传标识，测试结束恢复正常期限。
- 真实存储分页限制为每页一片，恢复能核对两页中已上传但尚未登记的分片，返回准确的 confirmedBytes；声明哈希不同返回 409。

## 状态与期限

页面实例身份在刷新后保留，新页面独立生成。服务端用行锁及条件更新保证有效写入资格唯一；资格为 330 秒，覆盖最长 300 秒的已签发地址。到期恢复轮换写入凭证。暂停阻止新授权，允许已经发出的 PUT 登记；进度从服务端实际分片核对结果恢复。单片最多三次尝试，写请求也有限退避，成功 PUT 的登记重试不重复发送文件。
