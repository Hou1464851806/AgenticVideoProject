# Issue #5：验证视频后在素材库定位播放

2026-10-10，在 Apple Silicon 上运行独立 Java 17 媒体 Worker，FFmpeg／ffprobe 为 `6.1.1-3ubuntu5`。Worker 使用单执行槽、512 MiB / 1 CPU，工作目录持久卷与业务 API 分离。RabbitMQ 为固定 digest 的 `4.3.6-management`。

## 真实边界与先失败后通过的验证

- PostgreSQL、Silo 与 RabbitMQ 集成测试核对持久通知、原子领取、同领取请求回放、不同领取请求冲突、当前尝试凭证和终态隔离。
- Worker 从真实 Silo 流式取回文件，独立核对字节数和 SHA-256，再运行 ffprobe 和完整 FFmpeg 解码。只有当前有效尝试可在同一数据库事务发布 VALID 素材与成功终态。
- 真实浏览器上传一秒 H.264 视频，验证媒体信息、原生播放器、授权 URL 的实际 Range 206 与时间定位；另一账号无法获取播放凭证。
- 损坏字节、错误声明哈希和 3601 秒样本分别显示失败原因、不进入可选素材，并经删除及 HEAD 确认后释放对象占用。
- VFR／无音轨样本保留原视频 time base；音画起点偏移样本保留原音频 time base 和 136 ms 偏移，不虚构音轨。
- 对领取且 ACK 后的实际 Worker 发送 SIGKILL。最初任务无法恢复；补上过期租约恢复后，业务 API 先查询重启执行器确认旧尝试不存在，再重新派发。最终恰好两个尝试、一份可播放素材。
- 实际 FFmpeg 执行中取消测试最初停在 CANCEL_REQUESTED。修复迟到完成回报与取消请求的竞态后，进程退出、清理本次工作目录后回报 CANCELLED；迟到成功不能发布素材。
- 心跳返回服务端权威租约时间，Worker 不自行推算租约。缺失时间字段先触发测试失败，再补上。
- 从真实 RabbitMQ 消费通知但不领取任务，最初 PENDING 永久等待；重新通知策略补上后，无新尝试也能再次收到同一任务通知。成功发布消息不被当作成功领取。
- 实际消息队列重投三次同一正在执行的任务，取消后只有一个尝试且没有遗留媒体进程。
- 重启恢复后的工作目录检查最初发现 4 个残留；补上独立 Worker 启动时只清理 UUID 尝试前缀的目录。此时尚无消费者启动，前一容器的进程已退出。
- 浏览器播放实际签名失效的 Silo 地址时最初无法恢复；补上有限重新鉴权，获得有效地址后恢复加载和原播放位置。没有权限时显示服务端拒绝原因。

## 运行边界

执行器无法访问时不凭租约过期认定进程已经退出。完成与失败回执可有限重试，重复回执须有相同尝试、生产键和载荷；不同或迟到回执不能修改终态。确定性媒体失败进入持久清理队列；暂时执行故障最多自动恢复三次，耗尽后保留原始文件以便核查。

完整 Maven 验证：14 项测试通过；Vue 类型检查、Vite 生产构建与 arm64 Compose 镜像构建通过。完整浏览器套件 11 项通过（约 2.5 分钟），包含中断后临时目录归零、三次真实重投通知与播放地址续期；已检查播放器截图。

小文件运行与恢复后的样本：媒体 Worker 133.7 MiB、RabbitMQ 126.9 MiB、Silo 98.04 MiB、业务入口 238.3 MiB、PostgreSQL 46.62 MiB。每次校验从对象存储以 32 KiB 缓冲读取；该样本不是 2 GiB 素材或并发压力验收。
