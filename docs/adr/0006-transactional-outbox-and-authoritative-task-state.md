# 以数据库任务状态配合事务 Outbox 派发异步工作

2026-10-14：[ADR-0017](0017-move-baseline-analysis-and-reading-tools-into-java.md) 将媒体及分析执行并入 Java 单体。用户随后明确保留 RabbitMQ 作为真实异步/解耦与简历实践，本 ADR 的数据库任务、事务 Outbox、确认投递和幂等原则继续使用；消费者改为同一应用内的有界阶段执行，不再使用独立 Worker 的 HTTP 领取/回报、租约和心跳。以下保留原分布式执行方案背景，新的具体形态以 M1 设计为准。

业务任务和待发送事件在同一 PostgreSQL 事务内提交，发布器确认 RabbitMQ 接收后标记已发送；执行者通过内部业务接口领取、心跳和提交结果，Spring 控制最终业务状态。与数据库提交后直接发送消息相比，Outbox 保留可恢复的发送意图，避免业务成功而派发丢失；代价是发布器、重复投递和幂等协议。该选择不提供跨数据库与消息队列的单次执行保证，必须结合执行占用、重试、取消和迟到结果校验。
