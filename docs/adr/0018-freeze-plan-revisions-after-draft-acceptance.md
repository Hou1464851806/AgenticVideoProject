# 用户接受草稿后才保存方案版本

2026-10-16 用户明确：Agent 通过多轮对话回答问题、理解需求，并在识别到制作意图后生成或修改剪辑草稿。校验通过的草稿仍可根据用户反馈修改；只有用户明确接受当前草稿，Java 才将其保存为不可变方案版本，前端在方案列表中展示。相较每次生成或修正完成即追加业务版本，此选择将未被用户接受的内部迭代与正式方案历史分开，代价是需要独立保存当前草稿及其校验依据。

制作会话与制作需求的生命周期不同：保存版本结束当前草稿制作，不结束持续问答或后续制作的会话。预览、正式导出及产物管理由前端与 Java 承担，不依赖用户操作 CLI 或重新运行 Agent。

后续访谈中，用户已确认 CL-Q1～Q4：接受草稿时原子创建并确认具体方案版本，正式导出另行明确请求；同一会话同时一份当前制作草稿，问答与讨论不丢弃它；本阶段不做已冻结版本的派生编辑；接受、预览与导出使用页面明确按钮，自然语言业务操作留待后续。此阶段边界补充 ADR-0015 的长期统一自然语言目标，不删除该目标。

用户追加确认：草稿回复下提供“预览”和“确认”。确认前也能通过 Java 渲染低清预览，完成后追加到聊天中播放；不能以隐藏的正式版本替代草稿预览。确认才冻结并进入方案列表，列表提供“导出”入口，生成的成片可播放或下载。草稿预览补充 M4 仅支持已保存版本预览的阶段范围，不改写其历史验收。

本决定补充 ADR-0001／0002／0007／0016 及 M2 显式保存语义。2026-10-16 用户已确认 CL-Q1～Q13 及[完整设计](../conversation-lifecycle-browser-design.md)，作为下一阶段实施基线；尚未开始实现，设计确认不代表浏览器接入已经具备。
