# 将基础视频分析与真实读取工具迁入 Java 后端

独立 Python Agent 已具备可注入工具执行器的决策与恢复核心，但旧基础分析执行仍依赖已经停止接入的 Python Worker 协议。M1 将上传后的 ASR、稀疏 VLM、文本 Embedding、证据检索和四个真实读取工具迁入 Java 模块化单体，Python 保留 Agent 核心并通过 JavaToolExecutor 使用真实反馈；上传后自动基础分析按来源分别开放，有界采样如实说明覆盖。媒体能力及既有渲染执行包装一起并入同一 Spring Boot 进程，移除跨进程 HTTP 领取/回报、Worker 租约和心跳，保留原有预览/导出规则。这避免为本机固定流水线恢复另一套业务执行生命周期，代价是迁写模型适配，并同步改接旧渲染、任务恢复和运行依赖。

用户进一步明确项目应有真实 MQ 异步/解耦实践，并希望在简历和面试中说明。因此撤回此前仅追求最少运行依赖的“删除 RabbitMQ”方案，保留 ADR-0006 的数据库任务、事务 Outbox 和消息投递思路，重构为同一 Java 应用内的生产者及有界消费者。数据库管理状态和回执，RabbitMQ 管理投递及积压，结果/下一步持久化后 ACK，重复消费幂等，临时失败有限重试，最终失败保留原因并进入死信；外部付费提交不确定不能因消息重投而自动重付。增加一项 MQ 运行依赖的代价，换取真实异步交接、资源限流、可核查可靠性实践和后续细读/制作复用。

本决定替代 ADR-0004 的独立媒体 Worker/固定 Python 分析职责分配，并调整 ADR-0006 的消费者位置及执行占用方式。M1 通过 CLI 验证真实问答，真实模式只开放四个读取工具，使用固定问答范围快照，未就绪来源说明缺口后结束本次尝试，检索通道可明确降级；按需细读、真实草稿校验与 Agent 制作接入留待后续里程碑。具体实现安排与验收见 [M1 设计](../java-tools-m1-design.md)。用户已确认最终共识，并明确要求暂不开始实现；本 ADR 的接受状态不代表代码已迁入或验收已通过。
