# 基于百炼分析模型与 DeepSeek Flash 推理的视频理解设计草案

日期：2026-10-14。状态：讨论用设计，尚未实施或运行模型评测，不替换现有已确认需求及 ADR。当前代码审查提交：`e65954da804b5ceab66e0d7e0be3493000847b30`。

后续 [VideoAgent 研究与设计](videoagent-evaluation.md)核对了时间记忆、定位／阅读／定向观察的工具循环，并细化信息缺口、模块职责与读取回执适配；沿用本文接口，不另建一套视频理解架构。

## 1. 目标与取舍

目标是在个人项目中，用百炼 ASR/VLM/Embedding 与 DeepSeek Flash 文本推理构建有出处的视频问答与剪辑定位能力，并能通过实际样本解释设计的效果和开销。参考 VideoRAG 的“提前粗分析、查询定位、针对问题细看”，不迁移它的模型、知识图谱、视觉向量或独立存储。[VideoRAG 论文](https://arxiv.org/html/2502.01549v1)

保留 LangGraph、Java 媒体处理、PostgreSQL、Qdrant 和已有任务机制。文本理解、决策和生成使用 DeepSeek Flash，ASR、VLM、Embedding 使用百炼对应模型；FFmpeg 的提取、采样、时间映射属于本地确定性处理。首版围绕中文课程、讲解和访谈；稀疏观察下的短暂动作、全片计数与精确运动边界不作保证。

视频理解在这里有可验证的定义：能找到相关内容、读到足够上下文、选择正确来源支持结论，并在信息不足时受控地补充观察。ASR/VLM 结果是模型观察，不是天然正确的真值；人标评测仍须核对原视频。

## 2. 借鉴 VideoRAG 的内容

| 参考思路 | 本项目采用方式 | 暂缓内容 |
| --- | --- | --- |
| 粗分析与细观察分开 | 全音频 ASR、基础帧观察；查询需要时补查局部 | 每次提问强制重描述全部候选 |
| 多来源检索 | 分开检索语音、画面描述、可见文字，在实际时间上合并上下文 | 本地 ImageBind 和直接视频向量 |
| 跨片段组织内容 | 时间窗口、全片内容目录、跨素材来源引用 | LLM 实体关系图 |
| 回到相关视频重新检查 | 按问题选择帧并调用百炼 VLM，保存观察 | 将 VideoRAG 的完整答案当作 Agent 的事实输入 |

这些取舍是产品设计判断，不是论文证明这套简化实现一定更好。收益由第 9 节评测验证。

## 3. 三层数据表示

### 原始观察：支持核查

保留现有 `evidence_segments`、句/词时间、帧身份与模型调用记录。语音、画面描述、可见文字分别保存。关键属性为素材、源文件哈希、分析代次、来源类型、原始时间、观察内容和提供方回执。

- 语音记录有句/词的模型时间戳；映射到原视频时间，但不宣称切点零误差。
- 单帧观察有实际 PTS 和 `observedAtMs`，不自动变成持续区间。
- 多帧观察引用输入帧身份和各自时刻；“两帧状态不同”与“期间发生某动作”区分，后者可能只是推断。
- 邻近转写不能证明视觉事实。定向视觉观察第一版不把转写当作画面依据输入；Agent 在观察完成后结合独立的转写推理。

### 时间窗口：支持检索和阅读

现有一句一个检索单元容易丢失代词、原因和完整观点。将相邻完整语句组合成有界窗口，原始观察不修改。可以从约 30–60 秒、相邻一两句重叠开始试验，同时设文本长度上限；这些是待评测参数，不是固定产品指标。长句与静默间隔需显式处理。

窗口文本由程序拼接，第一版不调用 LLM 逐窗口改写。每个窗口保留有序原始引用。语音窗口仍属于 SPEECH，视觉与可见文字继续分别入索引，避免将混合文本当作同一种事实。召回后按素材及时间组织上下文，窗口的起止只是检索范围，不是最终剪辑边界。

继续使用现有 Qwen 文本 Embedding、中文 BM25、Literal 与 RRF。不同模型/分析/窗口规则的索引分代重建，不能混用旧向量；重建窗口不重新支付 ASR/VLM。

### 内容目录：支持全片浏览

局部相似度检索不适合独立回答“这段课有哪几个步骤”“全片有哪些值得剪的观点”。提供覆盖完整时间线的分页目录，先由窗口原文摘录、时间及引用组成，不增加模型调用。

确需更易浏览的章节提要时，对已存转写按有界时间分组，经 DeepSeek Flash 生成带引用的导航概要，按需缓存。模型选择已提供的记录 ID，时间由程序回填；拒绝引用输入中不存在的 ID。提要仅用于导航，最终结论回读原始记录。没有可用视觉观察时，目录应说明它概括的是语音内容。

全片任务必须消费所有相关目录页或已覆盖全片的提要；不能只取 top-K 后宣称覆盖整段。首版固定时间分组即可，不先引入 LLM 语义分段、事件图或图数据库。

## 4. 对 Agent 的小接口

| Interface | 作用 | 必要返回信息 |
| --- | --- | --- |
| `get_video_overview(assetId, cursor)` | 浏览全片的内容分布与观察覆盖 | 有序目录、引用、下一页、分析/索引状态、目录覆盖范围 |
| `search_evidence(query, sourceKinds, ...)` | 复用现有混合召回；内部去重并返回窗口 | 原始引用、素材/时间、来源、检索可用性 |
| `read_video_range(assetId, startMs, endMs, cursor)` | 阅读同一原视频范围内的语音、画面和文字 | 独立来源记录、词时间、帧实际时刻、截断/分页状态、读取回执 |
| `inspect_video_range(assetId, startMs, endMs, question)` | 获得当前问题需要的额外视觉观察 | 新观察或待完成任务、输入帧身份、实际采样范围、用量和停止原因 |

上述接口是目标设计，现有 `search_evidence` 可扩展；`read_evidence_context` 可作为兼容入口。实际实现集中在视频理解模块，Agent 不选择存储、embedding 模型、抽帧算法或底层提供方参数。用户、项目、固定素材范围、预算和版本由业务注入。

资料查询工具返回观察而非一份再次生成的完整答案；这使问答和剪辑能共享同一批可核查数据。

## 5. Agent 如何根据问题访问视频

无需单独建立意图分类模型。由同一个 LangGraph Agent 根据用户目标选择信息来源和访问方式；规则规定权限与代价，模型决定如何寻找内容。

| 需求 | 首选动作 | 何时补查 |
| --- | --- | --- |
| “他说了什么、为什么” | SPEECH 检索，再阅读语句上下文 | 不因语音问题自动增加视觉调用 |
| “屏幕上的数字/物体是什么” | VISIBLE_TEXT/VISUAL 检索，核查原观察 | 没有可支持所问细节的画面记录 |
| “前后发生了什么变化” | 阅读目标范围的时间序列 | 现有帧不足，补充有序多帧；仍保留采样限制 |
| “整段有哪些步骤/亮点” | 浏览完整目录，再阅读选中范围 | 只对需要视觉确认的范围补查 |
| “找出某主题并剪辑” | 定位与上下文阅读，核查用户要求的视觉条件 | 再检查语句完整性和最终切点，进入已有剪辑流程 |

Agent 在每次工具反馈后重新判断：是否找到了相关位置、上下文是否完整、依据来源是否正确、是否满足用户约束。建议记录结构化的检查目标，例如“确认屏幕是否显示指定代码”，不记录或依赖隐藏思维链，也不把模型自评置信分数当成事实证明。

没有命中时，先检查分析/索引状态，再有限改写、浏览目录或切换来源。纯视觉目标没有任何候选时，可在预算内做更广覆盖采样，但不能假装局部补查解决了全片发现；可能返回“在已采样范围内未找到，覆盖不足”。意图不清楚才追问用户；缺少观察与等待任务完成不是意图不清楚。

## 6. 定向视觉补查

百炼视觉理解支持多图和视频输入，模型输入受 token 等限制；当前视觉模型的视频输入不理解音轨，需要独立 ASR。首版优先自行提取带实际时间的帧，便于控制输入量和引用身份。[百炼图像与视频理解](https://www.alibabacloud.com/help/en/model-studio/vision)

现有 `vision.py` 已调用百炼且分开返回 description/visibleText，但所有任务用通用单帧提示；`VisualInspections.query` 没有成为视觉模型的检查目标。最小改造是将补查问题传入观察调用并返回相关事实、输入帧引用和无法判断项，而不是只在通用描述中做字面匹配。

可先复用现有单帧实现，服务屏幕文字和静态物体问题。需要状态变化时再增加同一请求中的有序多帧，通常从每次最多 4 帧开始，附帧 ID 和实际时刻。模型一次多图与现有一帧一请求的回执不同，必须显式保存请求关联的全部帧，不能仅改提示词后继续假定一一对应。多帧输出引用已输入帧，程序核验身份；不能让模型自由生成时间。

定向提示契约：

```text
输入：检查问题、按时间排序的帧及其身份。
输出：可见事实及支持帧、可见文字、问题是否可据这些帧判断、无法判断项。
只把图像中确实可见的内容列为观察；过程/因果推断另行标注。
没有看到目标只说明本次输入未观察到，不推断整个视频不存在。
```

输出必须校验 schema、引用和记录大小；合法 JSON 不代表语义正确。程序可校验引用存在、属于授权范围且访问过，语义支持情况由人标评测核对。

补查结果追加保存到原分析的观察体系，并异步增量发布检索单元；当前轮次可用返回结果和读取回执立即继续，不等待向量索引更新。后续问题通过查询或范围阅读复用这些观察。范围覆盖、帧采样和可见事实分别表达，不能把成功调用解释为完整覆盖。

## 7. 预算、缓存与 LangGraph 恢复

模型调用次数、帧数、输入字节、token 用量、超时分别记录。一次请求打包多帧不代表费用只等于一张图。沿用既有项目授权与每需求累计新增调用规则，预算在业务后端预留/扣减，不随聊天消息、重试或子任务重置。当前代码只有每个复查任务的限制，共享需求预算尚需补齐。

缓存键包括素材哈希、分析版本、实际帧身份、采样规则、模型/参数和提示版本；问题导向观察另含规范化检查目标。通过范围读取复用已确认的通用观察，不将另一个问题的结论直接当当前问题答案。每次缓存读取仍检查项目权限。对于请求是否已计费不明确的状态，沿用当前回执规则，不能自动重付。

创建异步补查后，LangGraph 保存依赖并暂停，释放执行槽；分析完成事件恢复原轮次及预算。这是系统自动等待，与用户澄清区分。当前 `app.py` 对话运行时不领取分析任务，原地轮询等补查会使单执行槽无法推进。

百炼非实时 ASR 原生异步接口提供句/词时间；继续使用已有录音文件转写路径，无须为本设计更换 ASR。[百炼非实时语音识别](https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide)

模型职责按能力划分：DeepSeek Flash 负责文本推理与生成，百炼负责 ASR、VLM 和 Embedding。复用现有 DeepSeek 对话适配，并验证工具调用契约；各能力分别记录提供方、模型身份、用量及回执。

实施顺序：

1. 固定诊断样本，保存当前基线；实现窗口与范围阅读，不改模型。
2. 接入分页全片目录和单帧定向补查，补齐共享预算、回执与暂停恢复。
3. 根据状态变化类问题加入有序多图；根据全片问题需要加入缓存章节提要。
4. 分项评测决定后续增强，避免一次加入所有模块后无法解释收益来源。

## 9. 用什么证明这块是项目亮点

第一轮使用 3–5 个代表视频、30–50 个固定问题作为诊断起点，人工标注答案、正确来源及原视频区间。问题包含同义主题、名字/数字、需要上下文、全片步骤、语音提及但画面没有、画面独有细节、短暂文字、顺序变化及覆盖不足。剪辑样本另外标注独立观点、完整语句与画面条件。

对照：A 现有方案；B 加窗口/范围阅读；C 加目录；D 加定向补查。保持基础 ASR/VLM 和回答模型版本一致，额外观察的量单独记录。需要时固定工具脚本隔离检索收益，另做完整 Agent 验收，不把模型波动混同为某一模块的效果。补查比较使用独立工作副本，防止新观察泄漏到基线。

指标定义：

- 片段 Recall@K：标注的支持位置是否被召回，且来源类型正确。
- 答复支持率：可验证主张中，引用的原观察实际支持该主张的比例；仅引用存在不算支持。
- 全片遗漏：标注步骤/主题覆盖情况；top-K 局部准确与全片完整性分别衡量。
- 时间误差/剪辑完整性：最终边界与标注范围、独立观点的差异，另外核对导出。
- 错误否定：采样不足却声称“全片不存在”的次数。
- 开销：每小时基础分析成本、每问题新增 VLM 数/帧数/token、冷/热延迟、缓存命中率。

该样本规模不支持泛化或稳定 p95 承诺。输出失败分类：未采到、观察错、表示丢上下文、召回失败、排序失败、工具选择失败、回答无依据。先解决实际失败所在层，再考虑直接视觉向量、实体图或独立精排。

## 10. 简历与面试表达

当前可准确表达“设计方案”；完成实现与验证后才写“设计并实现”。没有测试结果时不填提升比例。

完成后的简历表述模板：

> 设计并实现面向视频问答与剪辑的多模态 RAG：通过百炼 ASR/VLM 构建带时间和来源的视频观察，结合混合检索、上下文阅读、全片目录与按需视觉补查；基于 LangGraph 完成检索—核查—补查循环，并实现需求预算、幂等回执及暂停恢复。

实测后补充：固定 `[N]` 个问题，支持率由 `[A]` 到 `[B]`，新增视觉调用均值 `[C]`、费用/延迟 `[D]`；注明样本类别与成本范围，不使用占位数字充当成果。

面试解释：视频转写和图像描述会丢信息，局部检索也无法覆盖全片。我把原始观察、检索窗口和目录分开，前者核查、后两者导航；Agent 先利用已有内容，只有具体问题缺少画面依据时才调用 VLM 检查原片段，并保存观察供复用。模型可决定找什么，业务控制范围和预算。用相同样本逐项对照，判断收益来自上下文、全片浏览还是额外观察。这是借鉴 VideoRAG 后针对产品约束的系统设计，不宣称自创模型算法或理解了所有帧。
