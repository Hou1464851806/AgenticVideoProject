# 对话会话、制作需求生命周期与浏览器接入

日期：2026-10-16（Asia/Shanghai）。状态：CL-Q1～Q13 及完整设计均已由用户确认，作为本阶段实施基线；第 1 步实施记录见[身份与契约验证](verification/conversation-lifecycle-step1.md)，后续步骤待实施。本文记录已确认的产品行为、最小技术方案、实施顺序和验收标准。原设计确认轮仅维护文档，未开始实现；用户现已另行授权实施第 1 步。本文保留设计轮的事实与历史核验，新增实现验证以步骤记录为准。

## 已确认目标

- 浏览器是用户入口，Agent 提供问答与多轮对话；识别到制作意图才生成或修改剪辑草稿。
- 草稿通过 Java 校验后仍未形成正式方案版本。用户不接受时可继续通过对话修改，再次校验。
- 用户明确接受当前草稿后，Java 将其保存为不可变方案版本，并由前端在独立方案列表展示。
- 草稿以聊天消息展示，下方提供“预览”和“确认”；未确认也能预览，预览完成后在聊天中追加可播放结果，不先保存正式版本。
- “确认”表示接受当前草稿，原子冻结版本并记录方案确认；方案列表中的“导出”明确请求正式渲染，成片可播放或下载。
- 接受一份草稿不结束整个会话；草稿与已冻结版本的预览、正式导出及产物管理由前端与 Java 承担。
- CLI 保留开发和验收用途，用户不需要操作 CLI；不扩大本轮为重写已验证的分析、检索或媒体执行。

术语见 [GLOSSARY](../GLOSSARY.md)，已确认的版本形成原则见 [ADR-0018](adr/0018-freeze-plan-revisions-after-draft-acceptance.md)，后台接入方式见 [ADR-0019](adr/0019-schedule-agent-through-a-python-worker.md)。

| 事实 | 代码与影响 |
| --- | --- |

| 基础设施存在，新 Agent 调度不存在 | Compose 无 Python 服务；现行 MQ 分派、消费和恢复仅支持媒体／分析类型；旧内部 tasks 协议默认返回 410 |
| 已有方案列表与版本媒体能力 | M2 保存写入现有 edit_plans／plan_revisions，前端 PlanPanel 可读取；预览、方案确认、导出与播放已有公共业务入口 |
| 当前草稿预览不能直接调用旧预览入口 | `render_requests`、`artifacts` 和相关外键都绑定正式 revision；草稿预览需要真实的草稿来源，不能提前保存隐藏版本 |

| 当前快照没有剪辑草稿身份 | AssistantDrafts 为未完成助手文本，并非剪辑草稿；不能将它直接作为待用户接受的结构化草稿 |
| 待澄清时不能直接插入独立问答 | `Agent.send` 在 checkpoint 有下一节点时拒绝普通消息；`await_input` 将匹配 wait_id 的文本作为原问题补答，新增问答需与挂起制作的恢复分开 |
| 停止／失败不回滚制作 | 理解可已合并新条件，DRAFT 可已覆盖待校验内容；取消或 INCOMPLETE 不恢复上一份合法草稿，不能因执行结束便重新开放旧稿确认 |
| 付费不确定保护已有，但重试适配未接通 | Python SQLite 对同调用的确定回执可复用，对 SUBMITTING／UNKNOWN 停止自动重付；旧 Java 重试检测不读取这些回执，Worker 不能用新 send 替代原执行恢复 |

以上为静态核对，不代表本轮重新执行了历史验收。

## 身份关联与持久化

| 对象 | 关联与权威 | 最小持久信息 |
| --- | --- | --- |
| 制作会话 | Java 管理；一会话可顺序处理多个制作需求 | 项目、公开消息顺序、当前制作引用、当前查看对象 |
| 用户消息／接纳轮次 | Java 管理；一次发送幂等接纳；补答关联原问题 | 原文、引用、发送时上下文、request key、message/turn/task 身份 |
| 制作需求 | Java 管理归属与可操作状态，Python 管理条件理解与内部草稿演进 | conversation、scope、制作 thread、当前条件及来源、当前草稿校验引用、编辑代次、是否已冻结／成为历史 |
| Agent 执行与尝试 | Java 管任务／attempt／lease；Python 管 execution／checkpoint／付费调用回执 | 固定输入、解析结果、执行 thread/execution、恢复来源、当前尝试及结果回执 |
| 已发布草稿消息 | Java 保存可恢复的公开投影，内容来自持久校验记录 | 制作、validation、draft_hash、requirements_hash、编辑代次和来源消息；不是正式 revision |
| 待回答问题 | Java 保存公开问题与关联；Python 保留挂起位置 | question_id、原任务／消息／制作、thread/execution、wait_id、问题状态及回答消息 |
| 方案版本 | Java 保存不可变版本；本阶段一制作最多保存一次新方案 V1 | 沿用 M2 内容、来源与 output_key→output_id 映射，附该次用户确认 |
| 预览／导出请求与产物 | Java 管理；独立于 Agent 执行 | 固定草稿或版本来源、输出、配置、素材、任务、尝试、产物与会话结果引用 |

优先给现有 conversations、edit_productions、conversation_questions、任务关联及渲染表做必要增量，不创建第二套消息、方案或任务体系。当前草稿只保存指向权威校验内容的引用及展示所需元数据，不再复制一份可独立变更的规范化方案。失败草稿可展示未完成内容及问题，但没有预览／确认资格。

本设计中“制作需求”专指视频制作目标；独立问答不会为了调度而伪造 edit_productions。既有 conversation_turns 可继续存放一次消息的接纳记录；补答虽有新消息和接纳任务，仍通过原问题／resumes_task 关联归属原对话轮次和制作需求，不能把新增数据库行误作一项新制作。

Java task 与 Python execution 不强制一对一：一次正常执行使用稳定映射；关联补答的新接纳任务需要指向原挂起 execution，恢复原预算和调用序号。Java 新 attempt、MQ 重投和服务重启不意味着新 Python execution。条件来源引用本次真实用户消息，不能总是指向首次制作消息，也不能让模型填写可信业务身份。

迁移只新增当前最大版本之后的文件，不改写历史 SQL。项目／会话／制作／校验归属由外键与边界事务共同保证；render request 和 artifact 保持一致的来源关联，EXPORT 仍必须使用具体正式版本及确认。

## 生命周期与并发规则

以下是面向用户的阶段视图，尽量从任务、问题和当前草稿引用推导，不新增与 tasks 平行的执行状态机。

| 事件或阶段 | Agent 任务 | 当前制作及界面 |
| --- | --- | --- |
| 发送普通消息 | PENDING→RUNNING | 理解本轮意图，不立即分配正式方案或改写制作条件 |
| QUERY／DISCUSS 完成 | SUCCEEDED | 保留当前制作、有效校验及待回答问题；视频事实继续需要证据 |
| ASK／缺关键条件 | WAITING_INPUT，释放执行占用 | 保存待回答问题，保留条件和草稿；允许独立插入问答 |
| 开始修改制作 | PENDING／RUNNING | 提升编辑代次，使旧草稿只读；保留最后已发布内容，不开放旧稿按钮 |
| Java 校验通过并发布草稿 | SUCCEEDED | 当前草稿可预览／确认；不创建方案版本，也不标成 WAITING_INPUT |
| 校验不通过或本轮未完成 | FAILED，公开原因区分 INCOMPLETE 与执行异常 | 保留新条件、未完成内容及问题；用户继续修改，不能恢复旧稿资格 |
| 停止当前 Agent | CANCEL_REQUESTED→CANCELLED，或排队直接取消 | 不结束制作，不回滚条件；挂起问题被明确停止时关闭其等待关系 |
| 用户确认当前草稿 | Java 同步业务事务，不调用 Agent | 创建并确认 V1，当前制作封存；草稿按钮失效，会话继续 |
| 明确另起制作 | 接纳新制作的运行任务 | 原制作及草稿成为只读历史，新制作不继承旧条件 |

同会话同时只允许一个正在排队／执行／取消中的 Agent 任务；待补答不占 Worker，也不阻止独立问答。预览任务不伪装成 conversation_turns 的 Agent 任务，不占会话 Agent 执行资格。首版单实例 Worker 有界消费，媒体仍走独立媒体队列。

接纳消息和确认／预览均在会话当前对象上序列化。消息意图尚未确定时，暂缓两按钮；理解为独立问答／讨论后可保留原有效资格，理解为制作修改则提升编辑代次并作废旧资格。Java 再核验具体草稿，不依赖前端禁用按钮解决竞争。若确认先成功，随后到达的修改不得改写已冻结制作，也不暗中创建 V2。

## Python 核心的最小调整

1. **分开当前消息意图和制作条件。** QUERY／DISCUSS 不经制作条件合并；只有明确的制作修改／关联补答更新条件。校验只在草稿或制作条件变化时失效。
2. **保留制作 thread，独立处理问答。** 制作 thread 保存范围、证据、草稿及等待；独立问答／讨论使用本轮 thread，读取 Java 提供的有界公开历史和制作摘要，不写挂起制作 checkpoint。无需为每种意图新增 Agent 或分类服务。
3. **先理解，再选择执行上下文。** 复用现有 Understanding 和 pre_understanding；补充是否关联某个待回答问题的最小字段。Java 核对问题仍有效后，只有真正补答才用原 wait_id 恢复；不能简单以 CONTINUE 或 QUERY 判断是否补答。
4. **解析结果持久复用。** 正常消息及关联补答都复用已经完成的有效理解；改造 apply_input 当前删除 pre_understanding 的路径，避免恢复时重复整体理解。格式错误仍允许既有预算内有限修正。
5. **显式注入可信身份。** Java 固定 task／turn／message 和目标 thread，Worker 恢复映射；新版入口不再由 NEW_REQUIREMENT 分支随机另建制作身份。CLI 保留原用途，不成为浏览器执行的子进程协议。
6. **公开上下文单一来源。** Java 提供截止当前用户消息之前的有界历史，当前消息单独传入，避免重复追加。映射进现有 messages/request；制作摘要帮助理解引用，不冒充视频观察证据。历史、草稿摘要、工具声明及证据共同受现有完整模型请求字节预算限制，不新增摘要模型或无限历史注入。
7. **预算与回执连续。** 入口理解计入本轮接纳任务的预算与用量；独立 QUERY／DISCUSS 使用独立预算。认定为关联补答后，该次理解的实际调用次数和活动耗时还须幂等归入原挂起 execution 的延续预算，保留原调用回执身份，不重复调用或重复计费；剩余额度不足不继续图执行。恢复原预算和调用序号，不重复图内理解、不因新接纳任务或新 attempt 清零原预算；恢复使用持久解析与原输入，不重新拼最新聊天。
8. **开放真实 DISCUSS。** 同步调整模式准入与提示词；讨论剪辑思路可以不读取视频，涉及视频事实时仍走已有证据规则。讨论不能未经制作意图授权生成草稿。

纯问答沿用 M1 在会话明确素材范围内新建问答快照的行为；制作、其修改、补答及故障恢复沿用制作固定 scope。针对当前草稿中具体内容的问答使用其明确来源范围，不将另一快照的证据混入原制作。新素材或分析发布不自动改写既有制作快照；依赖失效明确反馈，不自动新增分析或换 scope。

## Java 交互契约

路由沿用现有公共入口风格，以下是最小资源操作，不为每个图节点建 HTTP 端点；具体新增类名可在实施中按包内职责调整。

| 入口 | 传入与返回 | 必须保持的语义 |
| --- | --- | --- |
| 现有会话创建／消息／快照入口 | 用户原文、幂等键、明确引用；返回 message/turn/task | Java 鉴权；消息、任务及 Outbox 原子接纳。前端不选择 QUERY／DRAFT 或填完整制作表单 |
| 新版 Agent 内部任务交接 | task、attempt／lease、固定输入及 input hash；公开进度／解析／结果 | 独立 `/internal/v1/agent-runs/**` 入口，保留旧 tasks 协议退役；复用现有任务底座，绕过旧 EDIT_PROPOSAL 发布 |
| 解析后的执行接纳 | mode、与当前制作／问题的关系、条件增量及来源 | Java 固定制作和恢复关联、编辑代次及允许范围；不重写原接纳输入，不另调模型重复理解 |
| 草稿预览 | 当前草稿消息／validation／代次，单条 output_key，幂等键 | 后端取规范化内容；返回 request/task；不等待渲染、不保存版本 |
| 草稿确认 | 当前草稿消息／validation／两种 hash／代次，幂等键 | 不接纳客户端替换草稿；返回 plan/revision/confirmation 及输出映射 |
| 预览状态／播放／取消／重试 | 已接纳 request 或 artifact | 来源和权限固定；状态查询不新建任务；短期播放地址按访问取得 |
| 现有正式导出入口 | 具体 revision、该版本 confirmation、一个 output_id、规格及幂等键 | 只按用户明确点击导出接纳；正式版本与授权强约束不放宽 |

公共字段沿用现有 camelCase，Python 内部契约沿用 snake_case，在具体传输入口转换；不修改全局序列化规则，也不改 M2 草稿／条件哈希算法。

### 新版 Agent 输入和公开结果

固定输入至少包含 schemaVersion、项目／会话／消息／turn／task 身份、当前用户原文、有界历史、明确引用、当前制作摘要、待回答问题及关联代次。模型只产生内容和关系判断，可信身份由程序携带。

公开结果分为：ANSWER（含 QUERY／DISCUSS 及必要证据引用）、WAITING_INPUT（问题与原 wait 身份）、DRAFT_READY（持久 validation 与当前代次）、INCOMPLETE／FAILED／CANCELLED（结构化原因和可恢复信息）。Java 核对 scope 回执与证据身份后发布，不要求新证据伪造旧 conversation_tool_receipts；也不新增语义裁判模型。

进度只发布“理解需求／检索／读取／生成／校验”等活动，不发布私有推理。现模型适配为非流式，本阶段不要求逐 token 改造；持久化活动与最终消息通过已有 SSE 展示即可。

### 确认事务

1. 鉴权后可快速核对成功操作回执：同 key、同草稿重放原结果；同 key 改内容报冲突。成功重放不因草稿现已封存而失败。
2. 按下述统一顺序取得短事务锁，加锁后再次核对同 key 及目标绑定，随后才检查当前代次、校验、两种 hash、没有未决制作修改，以及引用依赖。两个并发请求不能都因加锁前查无回执而重复提交。
3. 从服务端持久条件来源组装原 SaveRequest，调用 ProductionSaves 保存版本；调用 ExportRequests.confirm 记录该用户对返回 revision 的确认。两者加入同一外层事务。
4. 保存操作回执、正式方案的聊天引用、制作已封存状态和公开事件，一起提交。任一步失败整体回滚。

按钮使用 USER_INTERFACE 来源；不能将助手的草稿消息冒充用户确认消息去调用 confirmFromMessage。本阶段不增加自然语言确认路由，也不把新自动确认语义扩大到既有 CLI save 或所有内部保存调用。

本阶段跨模块写事务采用一致的相对锁顺序：项目→会话→制作→task／attempt→question→版本或渲染请求／产物及相关引用依赖，只锁本次需要的对象。该顺序同时适用于消息／执行接纳、校验提交、结果发布、确认、取消、补答移交及草稿预览完成消息发布；不能仅在确认入口声明。既有共享方法若已先锁 task 再回锁会话，需要在本阶段实际新路径的外层提前取得相关锁；不照搬旧补答路径，也不引入通用锁框架。所有锁均限于短业务事务，不包围模型、网络分析或 FFmpeg 执行。

## Worker 交接与恢复

- Java 使用现有 AGENT_TURN 任务／attempt／执行回执及 Outbox，增加 Agent 专用队列路由和消费进程；消息只传身份，不传视频二进制或凭据。
- Worker 领取当前尝试和租约，取得固定输入；运行期间通过心跳和取消信号停止新增动作。Java 在新入口检查每次状态回报与发布资格，原 attempt 的迟到结果不得更新消息或当前草稿。
- 浏览器制作的 validate_edit_draft 也必须携带可信 task／attempt／lease 与编辑代次，并在提交 validation 和工具回执的同一事务中核对当前资格；仅在 DRAFT_READY 发布时检查不够。否则旧执行者可能追加“最新校验”并影响 ProductionSaves 的哈希判定。复用现有校验算法，增加提交接缝；已绑定浏览器生命周期的制作不得借旧 CLI 制作写入口绕过该检查，独立 CLI 需求保持兼容。
- 同一任务重投复用 Python execution、解析、checkpoint 和调用序号；不能重新 send 成新执行。Java 与 Worker 重启按原映射核对恢复，不在 MQ 消费回调中无条件清空状态。
- 待补答发布后原任务为 WAITING_INPUT，释放执行占用。补答新消息有独立接纳身份，并关联原问题／挂起执行；交接事务将问题标为 ANSWERED、原等待任务收束为 SUCCEEDED 并记录后继 task（结果表示已交接恢复，不表示草稿已完成），原 attempt 保持结束，关联任务取得挂起 execution 的恢复权。独立问答不会关闭它；另起制作则关闭旧等待关系并将其任务取消。
- ACK 的前提是结果／问题／失败或可恢复交接已经持久化。租约过期只表示需要核对执行与回执，不代表可以重新付费；Java 业务结果已提交则直接重放。
- 正常 ANSWER、DRAFT_READY 对应执行成功；INCOMPLETE 不伪装成成功草稿，公开问题／失败与执行结果分别记录。可恢复故障才开放 retry；预算耗尽、不可满足条件或 UNKNOWN 付费提交不靠重试按钮重置。
- 对明确可恢复失败，显式重试创建关联任务，旧失败保留；固定原输入与目标，复用可核对回执。当前制作已经修改或封存后不能借旧重试回写。Python checkpoint 已结束且无可恢复点时，不能将 resume 的只读返回冒充重试完成。
- 单实例 Worker 使用持久卷保存现有 SQLite checkpoint 与模型回执。不同运行不共享会被修改的 JavaToolExecutor scope/requirement 实例；同会话执行顺序由 Java 控制，现有本机锁继续保护 checkpoint。
- 继续关闭 legacy Agent／Worker 开关；新入口只开放本阶段需要的能力，既有媒体消费者和 M1／M2 内部工具保持兼容。

## 草稿预览的最小技术调整

用户预览的对象是某条草稿消息对应的已校验内容，不是尚不存在的方案版本。

- 预览入口由 Java 校验项目归属、当前草稿与持久校验身份；使用服务端规范化内容及源素材，不接受浏览器提供 FFmpeg 参数或替换片段内容。
- 复用已有 PREVIEW_RENDER 任务、Outbox、RabbitMQ、空间预留、FFmpeg、产物发布和播放鉴权；增加草稿来源，与正式版本来源区分，数据库约束保持来源归属正确。具体字段和迁移在契约确定后固定。
- 草稿来源以制作、校验、草稿／条件哈希和 output_key 定位；校验持久内容包含字幕与规格，不因预览重新分析、生成字幕或调用模型。
- 已接纳预览固定当时的内容与源文件；制作后来变化不改写它。确认不把已有草稿预览强行改成正式版本来源，也不将“复用草稿预览为版本预览”纳入必做范围。
- 成功产物与一条聊天播放结果关联，消息包含预览请求及来源草稿的引用；重复投递／恢复不重复追加。播放地址按访问取得，不把短期签名 URL 当作长期消息内容。
- 复用 conversation_messages 的结构化引用和公开事件；现有 AssistantDrafts 是助手未完成文本，不能冒充剪辑草稿或预览结果。
- 代码依据：[PreviewRequests](../backend/src/main/java/com/agenticvideo/business/render/PreviewRequests.java)、[MediaRenderer](../backend/src/main/java/com/agenticvideo/business/media/MediaRenderer.java)、[ProductionDrafts](../backend/src/main/java/com/agenticvideo/business/plan/ProductionDrafts.java)、[渲染请求迁移](../backend/src/main/resources/db/migration/V21__render_requests.sql)。

### 请求、产物与重放

| 来源 | 必需身份 | 允许操作 |
| --- | --- | --- |
| 草稿 | conversation、source_draft_message、production、validation、两种 hash、output_key | PREVIEW；revision_id／output_id 不伪造 |
| 正式版本 | revision_id、output_id；导出时另有 confirmation 与明确导出操作 | 既有版本 PREVIEW 或 EXPORT |

在现有 render_requests、artifacts、preview_intents 上扩展互斥来源及外键／检查约束；不能只放宽 NOT NULL 后失去请求与产物归属约束。草稿预览不分配永久 outputId／clipId，直接消费校验规范化内容。既有 EXPORT 的确认和来源约束继续保持。

同一来源草稿消息／validation／output_key 内复用运行任务或可用产物，缓存还固定源文件指纹、低清配置与 rendererVersion；不跨会话或不同草稿消息共享实际任务，不增加结果扇出映射。同内容的其他草稿消息是否共享媒体文件留待后续。

重放已接纳操作只读返回原 request；失败、取消或产物确认失效时，只有草稿仍是当前可操作草稿，才允许显式重试创建后继。修改、切换制作或冻结后，旧草稿仍能播放已有视频、查询既有请求，但不能借 retry、播放地址过期或缓存未命中重新渲染。签名地址过期只重新授权访问，不重新渲染。retry(A) 已关联 B 时重放仍为 B，不隐式创建 C。

产物成功发布、任务终态、执行回执与聊天播放消息在同一事务提交，使用 `conversation_messages.source_task_id=预览渲染任务` 的唯一关联避免重复追加，不创建 conversation_turns。播放消息包含 artifact/request 与来源草稿引用，前端按这些引用恢复，在聊天内展示 video 控件，不跳转到必须存在 revision 的旧 PlanPanel 入口。现有 SSE 触发器对独立媒体消息的 taskId 可能为空；若界面需要该字段，只增加 source_task_id 回退。失败／取消在该请求卡片显示，显式重试的新结果仍指向原草稿。

## 交互流程

1. 浏览器发送原文和明确引用；Java 鉴权并持久接纳消息及运行身份。
2. 系统调度 Python；Agent 读取会话上下文并理解本轮意图。
3. 问答返回有依据的答复，讨论返回讨论内容；均不自动创建正式方案版本。
4. 制作意图定位当前或新制作需求，生成／修改草稿并由 Java 校验；缺条件时在原会话澄清。
5. Java 发布公开结果，前端以消息框展示草稿及“预览／确认”。
6. 用户点击“预览”，Java 固定当前草稿内容并异步渲染低清视频；完成后追加聊天播放消息，不创建正式版本。用户可继续对话修改并重新校验。
7. 用户点击“确认”，Java 核对所见草稿与当前校验绑定，原子保存且确认版本；方案列表展示本次对话的产物，会话继续。
8. 用户在方案列表点击“导出”，Java 按具体版本与输出正式渲染，提供播放和下载。

### 等待、停止与恢复

- 制作等待“30 秒还是 60 秒”时，用户可以先问素材中的设备是什么；该问答独立执行，原问题和制作条件不被消费。输入真正回答原问题时，关联原 question/wait 恢复；无法确定关系时询问，不能将任意文本当补答。
- 30 秒草稿 A 改为 60 秒 B 时失败或被停止：保留 A 的历史和 B 的条件／未完成内容，旧 A 按钮保持只读。后续消息修改 B 并通过新校验后恢复当前操作资格，不增加自动撤销机制。
- 聊天停止只影响当前 Agent 执行或明确选中的挂起等待；媒体任务独立取消。预览 A 运行时可以生成 B；A 完成仍追加标明 A 的播放消息，不更新当前草稿。
- 确认当前 A 不要求先预览，也不要求等待已接纳 A 预览完成；后者仍使用原草稿来源。冻结后会话可继续问答和发起新制作，不能继续修改已封存 A。
- 已有确认或渲染接纳成功但响应丢失：重放返回原结果，或通过快照／列表查询找回，不新增业务结果。实际模型回执不确定则显示原因并停止，不自动重付。

### 前端与刷新恢复

复用 ConversationPanel、PlanPanel、projectEvents 和 Java 一致性快照。快照增加当前制作及操作资格、结构化草稿身份／内容、待回答问题和独立媒体请求，不只返回“最近一个 Agent task”。当前草稿即使早于最近消息窗口，也须能从当前制作引用恢复；历史消息正文继续按已有策略保留，不扩展长历史分页工程。

消息框按内容展示普通答复、证据、问题、草稿或预览结果；草稿下“预览／确认”取 Java 计算的当前资格。前端不通过解析 Markdown 识别可确认方案，也不将 AssistantDrafts 的未完成文本当剪辑草稿。

多输出只在预览／导出时选择一条；整体确认不允许只接受成功子集。方案列表展示本会话产物及其他可见方案，按钮绑定具体版本和输出；新版本不自动切换用户正在查看的对象。已确认的新版本直接提供导出，不再要求同内容二次确认；已有旧版本继续沿用原确认入口。

自然语言“确认／预览／导出”本阶段只说明对应页面按钮或澄清对象，不由模型直接执行。用户消息仍保留，不把它当作剪辑内容排除条件。SSE 展示持久化公开活动和结果，断线先恢复快照与游标；关闭页面不停止 Agent 或媒体任务。

## 验收标准

- 对话：先问答，再提出制作；Agent 才进入草稿流程。真实讨论与视频事实问答的依据要求分开验证。
- 迭代：拒绝当前草稿、修改指定输出、重新校验；未接受前无正式版本。问答插入不修改制作条件或丢失未变草稿的校验依据。
- 接受：仅接受用户实际看到且仍为当前的通过草稿；重复点击／丢响应恢复返回同一版本；并发修改不能接受过期草稿。
- 持续会话：冻结后可以继续问答及开始新制作；旧版本不改写，旧条件不隐式带入新制作。
- 页面：草稿消息提供“预览／确认”；刷新后恢复消息、当前制作、草稿及任务；断开 SSE 不取消任务；方案列表不混入未接受草稿。
- 异步执行：重复投递不重复发布；明确取消后旧执行者不能发布；恢复保留原制作与证据范围，付费提交不确定不得自动重付。
- 权限：浏览器通过 Java 项目鉴权访问，不能凭其他项目的会话、制作、校验或版本身份操作；内部凭据不交给浏览器。
- 草稿预览：未确认时可渲染低清视频，完成追加一条可播放聊天结果；重复请求／消息重投不重复发布；预览不创建方案版本、不写方案确认。与修改并发的历史结果不冒充最新草稿效果。
- 正式导出：草稿确认后方案出现在列表并已具有内容确认；明确点击导出才启动，取得实际可播放／下载成片，不重新运行模型。新草稿和正式版本两类来源的媒体规则及数据库约束分别验证。
- 验证记录：开发过程运行当前行为及所在模块、直接受影响模块；跨语言契约验证双方解析与哈希。共享任务／认证／MQ 改动覆盖关联模块，范围不明时扩大到服务全量。阶段收尾完成审查后运行一次 Java／Python 完整非付费回归及后端打包，补前端类型检查、构建和当前有效浏览器验收；真实付费模型与真实媒体验收单独报告并优先复用素材。

| CL-A15 | 重投、重启和迟到执行者 | 原 task/execution/checkpoint/调用回执关联可核对，确定回执复用、未知提交停止，不因重投新增付费提交；无重复正式版本或成功消息；旧 attempt 不能提交过期校验或发布结果 |
| CL-A16 | 失败重试与不确定调用 | 可恢复故障沿原输入关联重试，旧失败保留；实际 UNKNOWN 显示原因且无强制重付；预算耗尽不伪装可恢复 |
| CL-A17 | 快照、SSE 断线及签名过期 | 当前草稿／等待／媒体状态恢复一致；事件不重复应用；地址过期刷新授权仍为同一产物，不重渲染 |
| CL-A18 | 正式导出与播放下载 | 从确认后列表明确点击，真实生成 720p／1080p 成片并可播放／下载；不运行 Agent 或新增分析调用 |
| CL-A19 | 权限、双来源约束及完整迁移 | 其他项目身份被拒；仅草稿 PREVIEW 允许无 revision；EXPORT 仍有合法版本及确认；完整迁移和旧媒体路径回归通过 |
