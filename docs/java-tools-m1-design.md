## 已明确的范围

用户要求将基础视频分析和证据检索迁入 Java 模块化单体 Spring Boot 后端，实现 `list_assets`、`get_video_overview`、`search_evidence`、`read_video_range` 四个真实读取工具，通过 `JavaToolExecutor` 接入现有 Python Agent，跑通真实视频问答。设计遵循高内聚低耦合，不增加无必要框架，旧数据无需迁移。

上传后提前完成基础处理并保存结果，读取工具使用这些事实；`read_video_range` 按素材时间范围读取原始证据，向量召回用于 `search_evidence`。`inspect_video_range` 的按需新分析、真实草稿校验、保存及渲染分别属于后续里程碑，本轮不以它们作为完成条件。

Python 保留决策、预算、checkpoint、补答与恢复；Java 管理素材、基础分析、证据、索引和工具调用回执。PostgreSQL 保存权威证据，Qdrant 保存可重建索引。既有上传与对象存储优先复用。

用户补充明确：ASR、VLM、Embedding 三类模型均通过阿里云百炼模型 API 调用，由 Java 后端完成适配；允许同时整理 `backend/` 文件结构，并要求在 `backend/README.md` 持续维护 Java 后端说明。此补充已纳入用户最终确认的整体方案。

用户进一步明确：项目保留 MQ 作为实际异步/解耦能力，并作为简历与面试中可说明的实践。M1 保留并重构 RabbitMQ，替代之前删除 MQ 的方案；Java 模块化单体与 RabbitMQ 基础设施同时存在，生产者和消费者属于同一个 Spring Boot 应用。任务可靠投递、幂等消费、并发控制、有限重试及死信处理应有实际验收，不能把保留容器当成 MQ 能力已完成。

## 设计确认时的代码事实（2026-10-14）

- Python `ToolExecutor.execute(request)` 已有稳定调用身份及 `READY/PENDING/ERROR` 结果契约；自定义执行器必须显式注入素材及分析版本元数据。
- Java 旧工具入口绑定 `AGENT_TURN`、执行尝试和租约，工具名、字段及结果结构与独立 MVP 不一致。
- 基础 ASR、VLM 和文档 Embedding 执行还在 Python `analysis/` 中，独立 Agent 入口不会启动它们。
- 根 Compose 已将 Python 服务放入 `agent-integration-pending` profile，但 Java 仍向 `analysis.v1` 分派 ASR、视觉及索引任务；旧 Python 分析适配器没有调用入口，原分析链路因此不完整。
- 上传后的 Java 路径会准备稀疏帧；当前付费基础 VLM 由显式视觉分析端点触发，并非上传后自动执行。M1-Q1 已确认改为上传后自动执行有界基础视觉分析。
- Java 已有原始证据存储、混合检索、查询向量调用，以及媒体探测与抽帧实现，可抽取复用。
- 现有基础抽帧规则最多 25 帧，使用真实 PTS 和稀疏时间间隔，并明确 `complete=false`；它不代表逐帧覆盖。
- Python 目前将所有原始证据核验为正长度区间，真实视觉观察时刻需要独立处理；真实执行及观测标记还需去除 Mock 硬编码。
- Python 模型工具目录仍暴露按需细读，提示词也声明数据为 Mock；真实模式需要能力目录及提示语同步调整，不仅替换 HTTP 调用。
- 仓库已有带人工标签的中文语音视频、自然中文语音、无音轨可变帧率视觉视频，以及“语音提到猫、画面没有猫”的来源区分样本，可直接用于新链路验收，无需用户提供素材。
- 现有真实模型脚本未向旧容器转发 ASR live-test 开关，可能以跳过测试的结果报告成功；M1 验收入口须明确区分已运行通过与未验证。

上述事实已经过本轮只读代码核查，历史测试和验收记录不能代替重构后的新链路运行结果。

## 模块与运行形态

一个 Java Spring Boot 应用，按业务职责组织 package，不新增通用插件框架或模型网关：

| 模块 | 拥有的职责 | 主要协作 |
| --- | --- | --- |
| assets/upload | 原始素材、上传完成、探测信息、项目归属 | 上传完成事务接纳媒体准备任务 |
| media | 探测、音频提取、抽帧、既有 FFmpeg 编译执行、工作目录 | 为分析与既有渲染提供本地媒体能力 |
| analysis | ASR、基础 VLM 流程、模型提交与结果记录 | 调用百炼适配，将原始观察交给 evidence；按来源推进阶段 |
| bailian | ASR、VLM、Embedding 的提供方协议适配 | 三个具体客户端共享必要的 HTTP/认证配置，供分析和检索调用 |
| evidence/search | 原始证据、目录、检索单元、Embedding 与索引、混合召回 | 读取素材及已发布分析；从 PostgreSQL 回查权威记录 |
| tools | 四工具分派、可信问答范围、参数及版本校验、回执与错误反馈 | 调用业务入口，不复制查询或模型规则 |
| jobs/task | 任务接纳、原子占用、阶段执行、取消、结果发布与重启恢复 | 分派固定任务类型，不理解消息连接或模型提示词 |
| messaging | Outbox 派发、RabbitMQ 路由、确认与死信 | 用有界消费者调用任务入口，不复制业务规则 |
| plan/render | 已有方案、确认、预览、导出及产物发布 | 复用原业务规则，改接本机媒体执行 |

模块通过少量业务入口直接调用；事务不跨模型请求或 FFmpeg。工具执行主要入口为 `execute(可信上下文, ToolRequest)`。复用现有 SQL、模型参数、索引策略与 FFmpeg 编译逻辑；通过拆分职责消除旧大类中的跨业务耦合，不另加一套同名转发层。

PostgreSQL、Silo、Qdrant 和 RabbitMQ 保留，上传和对象存储接入优先复用。Java 媒体 Worker 的能力并入业务应用，生产与消费改为同一应用中的 messaging 模块和后台业务入口，去掉 HTTP claim/report、跨进程 Worker 租约与心跳。同步调整 Maven、Compose、Dockerfile、启动脚本、工作目录和字体/FFmpeg 依赖。旧 Agent 对话任务入口明确不可用，不再创建无人消费的任务。

数据库负责任务/业务状态、Outbox 和幂等回执；RabbitMQ 负责异步投递和任务积压；消费者的并发/prefetch 负责约束执行资源。本机定时任务只派发 Outbox、接纳到期步骤及核对需要恢复的执行，不建立第二条绕过 MQ 的普通任务执行链路。浏览器公共事件流继续承担业务状态通知，读取工具继续 HTTP 调用。

### RabbitMQ 最小重构

- 保留两类工作队列：媒体队列用于探测、音频提取、抽帧及已有渲染；分析队列用于 ASR 提交/查询步骤、基础 VLM、Embedding 和索引构建。使用固定 routing key 分派任务，队列名在实现中统一，不按每个素材创建队列。
- 上传接纳或阶段推进时，在同一数据库事务内保存任务/下一阶段及 Outbox。消息只带事件 ID、任务 ID、消息版本等少量身份；模型输入、视频/帧数据、凭据和权威任务参数从数据库或存储读取。
- 保留 durable 队列和持久消息；发布器处理 publisher confirm 与未路由退回，仅确认被正确路由并接收后标记 Outbox 已发送。MQ 不可用时任务与未发送 Outbox 留在数据库，有限退避后继续派发。
- 消费者通过任务 ID 和执行代次做数据库原子占用。阶段结果、失败状态或下一步持久意图提交后才 ACK，不在移交内存线程池后提前 ACK；终态任务重复消息直接核对后确认，运行中重复消息由占用及进程内活跃执行核对防止重复动作。
- 使用有界消费者直接执行阶段，媒体初始并发 1、prefetch 1，分析先设小并发。避免消费者提前 ACK 再交给无界内存队列。ASR 异步等待保存提供方任务 ID 及下次查询时间，当前步骤结束后 ACK；到期查询意图再经 Outbox/MQ 派发，不长时间占用媒体执行资源。
- 可确认安全的临时失败通过数据库记录尝试次数、下次执行时间和 Outbox 有限重试；不使用立即 requeue 无限循环。不可恢复/耗尽失败保存原因并进入配置好的死信队列，死信用于排查，数据库仍是任务失败的权威记录。
- 付费提交不确定时保留回执并停止自动重付，即使 MQ 重投或人工重放死信也先核对原提交。已知 ASR 任务继续查询；已保存响应和向量复用。消息重复投递不等于业务或费用可以重复。
- 单体当前按单实例运行，不重新引入跨进程 Worker 心跳/租约；保留数据库执行代次和取消检查。重启核对旧运行状态及模型回执，再为可恢复阶段经 Outbox/MQ 发送新执行意图，拒绝迟到结果发布。
- 不新增专用重试框架、延迟消息插件、复杂交换机拓扑或 MQ 请求/响应协议。普通阶段间通信采用明确任务接纳；Python 不直接订阅 MQ。

Publisher confirm 与消费者 ACK 是不同确认；重复投递依然要求业务幂等，不承诺外部模型恰好执行一次。死信转发也不能替代数据库失败记录。参考 [RabbitMQ 确认机制](https://www.rabbitmq.com/docs/confirms)、[死信交换机](https://www.rabbitmq.com/docs/dlx)。

仓库根 Maven 聚合入口改为指向 `backend`。文件移动、package/import 及测试位置调整与模块实施同步完成，并核对 Docker COPY、Compose build、脚本和测试工具引用。文件结构调整围绕真实职责展开，不将所有模块机械拆成 controller/service/repository 多层转发，不额外拆 Maven 子工程。

`backend/README.md` 是 Java 后端操作入口，维护运行职责、实际目录、启动/构建、基础设施及百炼配置、上传基础分析链路、工具和 Python 接入、任务恢复/费用不确定行为、测试与真实验收。架构细节和验收结果链接 `docs/`，避免复制全部规格。实施期间清楚标识当前与目标结构；最终命令必须在新结构下验证，不能把规划中的命令当成已经可运行。

## 基础分析和事实发布

上传完成后依次接纳探测及媒体准备；有音轨时做全音轨 ASR，无音轨记为不适用；并行分支做有界稀疏抽帧与基础 VLM。原始语音、画面描述和可见文字保存于 PostgreSQL，并保留素材时间映射、来源、分析版本、必要模型响应、提供方任务/请求身份及实际用量。

ASR、VLM 和文档/查询 Embedding 全部由 Java 通过百炼 API 调用。三个具体适配器保留各自的输入/输出和同步/异步协议，共享必要的认证、HTTP 配置与错误解析；模型回执、预算和阶段发布由业务流程管理，不借统一提供方引入通用模型网关或统一对话接口。使用现有模型配置作为迁写起点，兼容性在实现及真实联调时核对。基础视觉先沿用最多 25 帧、最大边长 960、单帧不超过 1MiB 等现有配置；记录真实采样时刻，不把这些参数解释为准确率或完整覆盖保证。不增加 CLIP、额外摘要模型或必选精排模型。

目录基于已保存语音、采样观察及阶段状态生成，用于时间导航，不作为精确引用。检索单元引用原始证据，完成文档 Embedding 后写入有界索引代次，验证成功才发布。ASR、视觉和索引分别开放，失败只影响对应阶段；索引失败重建已有证据的派生索引，不重新执行成功的 ASR/VLM。

数据库是权威状态。未发布的 Qdrant 数据不能召回；查询使用问答快照中的索引代次，不能依赖迟到任务写入的 active 标记。对既有索引做重建无需迁移旧运行数据。

## 本机任务与模型恢复

任务与 Outbox 先持久接纳，通过 RabbitMQ 投递到同一 Spring Boot 应用的有界消费者。定时派发和启动核对保证未发送意图能够继续发送；MQ 重投与执行代次核对保证重复消息不重复业务动作。媒体执行初始并发 1，分析设小的可配置并发上限；数据库控制任务状态，消费线程并发限制实际运行资源。

模型请求发出前保存提交身份和输入关联。ASR 已收到提供方任务 ID 后只查询该任务，等待期间不占媒体线程；已保存模型响应或向量可以复用。提交已发出而结果不确定时，保存不确定状态，停止自动重付；解析失败也保留已发生调用的记录。纯读取和能够确认未提交的临时错误可有限重试。

进程重启后按持久阶段核对，再经 Outbox/MQ 继续可恢复步骤：数据库读取与可重建媒体处理可以安全重做，已知远端任务继续查询，不确定付费提交需要核查。取消阻止新动作和后续发布，媒体进程有超时和取消清理；不能声称撤销已发生的远端请求。执行代次及取消标记用于拒绝迟到发布，不再保留跨进程 Worker 租约机制。

既有预览/导出继续冻结方案版本、素材、渲染规格和产物身份，沿用确认、幂等、发布、播放及清理规则。任务仍须有本机执行者；仅替换执行包装及运行依赖，不新增 Agent 制作接入。

## 问答范围与四工具契约

CLI 指定 Java 地址、项目及可选素材范围，通过现有本机内部凭证取得 Java 创建的问答范围。内部 CLI 是可信本机调用者，项目/素材均由 Java 核验；模型只提交工具参数，不能创建权限范围或填写认证凭据。浏览器项目鉴权规则保留，凭据不进入提示词、工具参数或 trace。

Java 为每次问答执行保存稳定范围身份及素材、分析版本、已就绪来源、可用目录/证据范围和索引代次。Python checkpoint 保存该范围身份，补答和恢复重新读取原快照并注入 `assets`，不从当前最新 heads 重建上下文。普通后续消息在需求的原素材范围内取得新的就绪快照，并核对/失效不能复用的历史观察和覆盖。持续分析和重建不能改变正在进行的问答；必要依赖不存在时明确失败。

四个工具沿用 `call_id/tool_name/arguments/request_hash`，结果沿用 `READY/PENDING/ERROR` 结构。M1 四读取工具不创建需要 Agent 自动等待的后台任务；未就绪返回来源状态和明确反馈，部分来源可用时返回已有依据并说明缺口。传输中断或执行尚未核对明确停止，不伪装成空结果，也不通过轮询强行恢复。

| 工具 | 行为 | 正确性约束 |
| --- | --- | --- |
| list_assets | 查询固定素材范围及探测/来源状态，分页 | 返回真实范围，分页累积不覆盖前页；未探测素材明确标识 |
| get_video_overview | 查询固定分析版本的时间目录，分页 | 导航与原始引用分开；分别返回分页状态和来源覆盖 |
| search_evidence | 稠密、BM25、原文各通道独立召回，融合后回查 PostgreSQL | 素材、来源和索引代次在召回前过滤；通道降级与候选截断可见 |
| read_video_range | 按素材、分析版本、来源可用性和半开时间范围读原始记录 | 语音使用时间交叠，视觉点观察使用范围内时刻；保留原始时间与上下文，不依赖向量相关性 |

工具回执按问答范围及调用身份唯一保存，校验工具名、参数和重新计算的请求哈希；同一身份内容不同明确冲突。已经完成的调用重放复用结果。查询 Embedding 的提交及结果也与调用/查询身份关联，不由请求重放创建新的付费调用。

对同一快照及相同检索条件，先形成有界候选排名并保存到查询记录，后续 cursor 分页复用该排名和已取得向量，不能每翻一页重新执行付费召回。目录和范围查询采用稳定排序。服务器按既有 32KiB 工具反馈上限分页，单条记录超限明确错误，不静默截断文本或 JSON；检索候选上限及实际分析缺口单独返回。

语义通道不可用时继续使用可用的 BM25/原文，并报告通道状态和费用不确定记录；没有可用通道则明确不可用。安全异常按明确失败分类处理；参数错误可修正，权限、依赖失效、未就绪和不确定提交不能循环当成参数问题修复。Python 保留现有模型/工具预算，Java 对真实调用接纳与重放核验，不机械复制旧每任务 12 次工具上限。

必须验证：

1. 从现有上传入口开始，真实 Java 媒体/百炼/索引链路执行；使用四个真实工具，结果标记和 trace 不含伪造 Mock 数据。
2. 目录、检索和范围读取的分页完整性、结果大小、来源、时间和分析覆盖均可核查；引用可对应原始视频及权威证据。
3. 语音与视觉独立就绪；所需来源未就绪时真实说明缺口；不可用能力不会落到 Mock 或无人消费任务。
4. 同一次问答、补答和进程恢复使用原快照；后来发布的分析不改变当前结果，新普通消息可以获取更新后的来源状态。
5. 同一调用身份复用回执，参数冲突被拒绝；查询翻页复用排名；索引失败不重新付费分析，已知 ASR 任务查询恢复，不确定提交不自动重付。
6. Embedding/Qdrant 等故障下可用通道继续工作，降级和未命中范围明确；取消及执行代次检查拒绝迟到发布。
7. 既有预览/导出真实 MP4 通过必要播放、ffprobe、音画/时长及确认/发布规则回归；不新增 Agent 到成片链路。

9. 真实 RabbitMQ 验证：数据库提交后 broker 暂停，任务/Outbox 保留并在恢复后继续；重复投递不重复分析/渲染或付费；结果落盘后 ACK 前断连，重投复用结果；有限重试及死信原因可核查；队列积压时实际媒体并发保持上限。模型响应不确定时的重投使用受控提供方验证，避免故障验收真实重复付费。

保留每次真实运行的模型及工具调用身份、用量、最终 JSON、样本引用和 Langfuse trace。真实调用只针对固定小样本及必要验收，不运行依赖旧 Python Worker 的整套历史付费浏览器测试。

## 完成定义与范围

M1 完成意味着：现有上传入口 → Java 单体基础分析与证据发布 → Python CLI 经四真实工具完成可核查问答，且已有媒体预览/导出执行能力在单体中保留。旧数据不迁移，必要时重建本机业务数据和派生索引；不把允许重建旧状态解释为可抹除新付费回执。

M1 不新增 CLIP、精排模型、按需细读、真实草稿校验、Agent 制作接入、Python FastAPI、自动分析等待恢复、分布式调度或动态工具平台。旧协议删除范围以迁入后的真实执行路径为准，最后清理废弃代码与依赖。

RabbitMQ 是 M1 持续保留的基础设施。后续按需细读和 Agent 制作接入可以使用同一任务/Outbox/MQ 路径，按实际资源隔离需求调整路由，无需先移除再引入。简历描述以实际验收的异步处理、可靠投递、幂等、并发和故障恢复为依据；本机单实例不宣称集群高可用或未经验证的吞吐规模。
